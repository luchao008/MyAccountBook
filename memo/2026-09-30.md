## 修复：流水编辑改分类保存不生效（后端 · 真 bug）

**症状**（luchao 报）：流水页点一笔 → 编辑页改分类 → 保存 → 返回，**分类没变**。
（改金额 / 日期 / 备注都正常，只有分类不动 —— 这一点是定位的关键线索。）

**根因**：`src/transaction/transaction.service.ts` 的 `update()` 里，`categoryId` 分支只处理了
「清空分类」（`entity.category = null`），**漏了「改成另一个分类」**。

`findById()` 用 `relations: ['category', 'account']` 取实体，**旧分类对象**就挂在 `entity.category` 上。
只改 `patch.categoryId` 时，TypeORM 以**关系对象**为准，把 `category_id` 回填成旧值。
于是接口 200、响应体也"看着正常"（其实是旧值），库里根本没变 —— 前端完全无从察觉。

同类坑在这个方法里**已经处理过一次**（`accountId` 分支传了新实体给 `entity.account`），
category 这一支漏了。**这已是第 4 次踩「改外键必须同步关系对象」，且是同一处的漏网分支。**

**修复**：接住 `assertCategoryValid()` 的返回值（它本来就返回校验通过的分类实体，原先被丢弃），
在 `patch.categoryId` 的同一分支里同步 `entity.category = finalCategory`。

**判据（三条都做过负向验证：回退修复立即变红）**：

| 层 | 位置 | 结果 |
|---|---|---|
| service 单测 | `test/transaction.service.test.ts` 新增「★ 改分类：从一个分类改成另一个同类分类，应真的落库」 | 修复前拿到旧 id（红）→ 修复后绿 |
| HTTP 回归 | `scripts/regression-test.sh` 新增 2 条：`switch category -> new id` + `switch category persisted` | 90 PASS / 0 FAIL（原 88） |
| 真实浏览器 | 新增 `scripts/verify-edit-category.mjs`（登录 → 建临时账本 → 造流水 → UI 改分类 → 返回） | 21 PASS / 0 FAIL |

⚠️ 回归里那条 `... persisted` 特意**再查一次详情接口**才下结论 ——
只看 PUT 的响应体会被"回填旧值"骗过去（返回的就是旧 id）。

⛔ **判据盲区（这次的教训）**：原来只有「清空分类 → null」一条用例。
**"改成 null" 与 "改成另一个非空值" 是同一个坑的两半，只测一半等于没测。**

## 需求：记一笔表达式行去掉 `direction: rtl`

rtl 本意是让溢出从**左侧**截断（最新输入的那一段永远可见）。
但 `+` / `-` 是**中性字符**，在 rtl 上下文里会被重排到整串**左端** —— 表达式读起来是乱的。
去掉后顺序正确（截图实证 `12.5+3-2`），代价是超长时改为**右侧截断**。
取舍：**顺序正确 > 尾部可见**。此决定推翻了 memo/2026-09-26 里"rtl 左截断"的写法。

### 这一轮踩到的坑（都已写进 `docs/工程约定与踩坑.md`）

1. **H5 浏览器里根本不发 `touch` 事件** —— 只绑 `@touchstart` 的拖拽，用鼠标拖**一点反应都没有**，
   看起来像"旋转没实现"。修法：同时绑 `@mousedown`，`mousemove`/`mouseup` 挂到 `document`。
   另外移动端要 `touch-action: none`，否则浏览器把拖动判成滚动手势、`touchmove` 不派发。
2. **旋转的方形容器会把包围盒撑到 √2 倍** → 整页横向溢出（375 档实测文档宽 387）。
   `.ring-holder` 加 `overflow: hidden`（裁掉的只是四角空白，环怎么转都在里面）。
   顺带把 `ringSize` 改成 `min(260, 屏宽 − 64)`（body padding 32 + 画布 PAD 32）。
3. **用负 margin 扩大触摸区会被判"压邻居"** —— 44 的渲染盒真的超出 28 的占位。
   改用 **`::after` 伪元素**撑触摸区（不参与布局与重叠检测）。
4. **`overflow: hidden` 裁掉的是空白**这件事要判断清楚再裁，否则会把内容裁没。
5. **picker 的层级要抬「整组」**：只抬外层 `.uni-picker-custom` **没用**，
   真正画日历面板的是最里层 `.uni-picker-container`。判据也必须落在最里层。
6. **页面有两个 `<picker>` → 两份 `.uni-picker-container`**，其中一份 `display:none` 高度 0；
   脚本 `querySelector` 拿到它会得到"高度 0"的假失败。
7. **uni-app H5 的页面滚动容器不是 `window` / `uni-page-body`**，实测 `document.scrollingElement`
   才动。探针里写死 `uni-page-body.scrollTop` 会一直读 0，而页面其实滚了 ——
   **"读不到滚动量"≠"没滚动"**，别拿它当断言。
8. **数据量不足会让"滚动"断言假红**：8 条数据页面根本滚不动，`compact` 永远不出现。
   造数要造够（本轮用 15 条）；实在不确定就把"能不能滚"写成**前置断言**或只打诊断。
