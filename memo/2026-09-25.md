## 三、环境问题（都已解决，可复用）

### 3.1 PATH 缺 `/usr/local/bin`
这台 Intel Mac 上 `pod` / `node` / `npm` 都在 `/usr/local/bin`，但 Cuckoo 的
shell 环境 PATH 只有 `/usr/bin:/bin:/usr/sbin:/sbin`。**每次调用都要手动**
`export PATH="/usr/local/bin:$PATH"`。已写入 `~/.zshrc`（含 UTF-8 locale），
但工具环境的 shell 不读 zshrc，所以命令里仍需显式 export。

### 3.2 GitHub clone 慢 → git 代理重写
CocoaPods 拉 SDWebImage 时卡在 5MB 不动（GitHub 直连被限速）。
配置全局 git 重写（**已生效，影响所有仓库**）：

```bash
git config --global url."https://gh-proxy.com/https://github.com/".insteadOf "https://github.com/"
```

实测 `gh-proxy.com` 最快（1.1s），`gitclone.com` 次之（2.0s），`ghproxy.net` 最慢（8s）。

### 3.3 Xcode 26.3 缺 iOS 模拟器 runtime
本机只有 iOS 14.5/17.4/17.5/18.0 的旧 runtime，**Xcode 26.3 不认**，
导致 `xcodebuild` 报 `Unable to find a destination`。
解决：`xcodebuild -downloadPlatform iOS`（下载 iOS 26.3.1，10.47GB）。
后按要求删除旧 runtime（14.5/17.4/17.5，释放约 12G），保留 18.0 + 26.3.1。

⚠️ 下载大文件时 JS 工具层有 60s 超时，必须 `nohup ... &` 后台跑 + 轮询日志。

### 3.4 系统 Ruby 2.6 + Xcode 26 编译原生 gem 失败
`gem install cocoapods` 编译 `nkf` 扩展时报
`No rule to make target .../ruby/config.h`。
**结论：本机现有的 pod 1.9.1 可直接用**，不必升级（实测 pod install 成功）。

## 四、踩坑记录（写代码时踩到的）

### 4.1 AFNetworking 的 baseURL 路径被 path 吃掉
```
baseURL = http://127.0.0.1:7001/api
[manager POST:@"/auth/login" ...]   → 实际请求 http://127.0.0.1:7001/auth/login（丢了 /api）→ 404
```
**原因**：AFNetworking 把以 `/` 开头的 path 当**绝对路径**。
**修复**（`ABHttpClient`）：去掉 path 开头的 `/`，并保证 baseURL 以 `/` 结尾。

### 4.2 `copy` 前缀的属性名触发 Cocoa 命名规范
`@property UISwitch *copySwitch;` → `error: property follows Cocoa naming convention`。
**规则**：属性名**不能以 `copy` 开头**（`copyAllSwitch` 也不行，只要以 copy 打头就报）。
改名为 `inheritCategoriesSwitch` 解决。

### 4.3 `static const` 不能放在 `@interface` 内
`ABTheme.h` 里把 `kSpace1` 等写在 `@interface ... @end` 之间 → 编译错误。
**修复**：移到 `@end` 之后、`NS_ASSUME_NONNULL_END` 之前。

### 4.4 JS 模板字符串会转义 `\n` 和 `\"`
用反引号模板字符串写 OC 源码时，`@"a\nb"` 里的 `\n` 会变成真换行，
`\"` 会变成 `"`，导致 OC 语法错误。
**修复**：涉及转义的源码用 `String.raw` 包裹。

### 4.5 xcodeproj 生成的工程需要手动补平台设置
`objectVersion = 46` + `compatibilityVersion = "Xcode 3.2"` 会让 Xcode 26
判定「Supported platforms is empty」，destination 解析失败。
**修复**：生成后 `gsub('objectVersion = 46;', 'objectVersion = 56;')`，
并在 project 级 + target 级都写 `SDKROOT` / `SUPPORTED_PLATFORMS`，
还要用 `Xcodeproj::XCScheme` 生成**共享 scheme**。

### 4.6 分类图标是 `img:<中文名>` 格式，不是 emoji
后端分类 `icon` 字段两种形态：emoji（如 `🏠`）或 `img:日常用品`。
后者是前端的**图片图标**体系（94 张 PNG，中文名→拼音文件名）。
**移植**：`scripts/gen_icon_map.js` 从 `cat-icons.ts` 生成 `ABIconMap`，
拷贝 PNG 到 `Resources/cat-icons/`，`ABIconView` 按前缀分流渲染。
⚠️ 生成的 PNG 加到工程时必须**逐个 new_reference**，folder reference 会报错。

### 4.7 模拟器 iOS 26 的 emoji 字体缺失
日志有 `Requested font not available ... AppleColorEmoji`，
少数 emoji（如 🏠）在模拟器上显示为方框 —— **真机正常**，不是代码问题。

## 八、登录闪退 bug 修复（同日）

### 现象
用户反馈「一登录就闪退」。崩溃报告显示 `EXC_BAD_ACCESS / SIGSEGV`，
调用栈是 `-[ABLoginViewController setLoading:]` 无限重复 → 栈溢出。

### 根因
`@property (nonatomic, assign) BOOL loading` 会自动合成 `setLoading:`，
而我在同一文件手写了 `- (void)setLoading:(BOOL)loading`，方法体内又写 `self.loading = loading`，
于是调回自己 → 无限递归。

### 修复
方法改名为 `updateLoading:`（6 处调用一起改）。

### 排查与预防
写了脚本扫描全工程的同类冲突：`- (void)setXxx:` 方法名与同文件 `@property xxx` 撞名。
结果只有 `ABCategoryPicker.setSelectedId:` 命中，但它方法体内用的是 `_selectedId`（直接访问 ivar），
所以安全，不需要改。

**教训**：OC 里想给属性加副作用，要么覆写 setter 且用 `_ivar`，要么另起方法名，
绝不能「同名 + self.property 赋值」。

编译 **BUILD SUCCEEDED**。⚠️ 必须传 `-derivedDataPath` 指向项目内，否则沙箱拦 DerivedData 写入
报 `BUILD FAILED`（**看着像代码错，其实是环境**）；**判据是日志末尾的 BUILD SUCCEEDED，不是退出码**
（收尾时沙箱会拦一个无关的 `~/.swiftpm` 删除，让退出码非 0）。

### 发现的问题

1. **4 个假控件**（`ABCategoryViewController`）—— 违反项目铁律「别做假控件」：
   「搜索分类」确定按钮 / 「批量隐藏」/「批量删除」三个都是 `handler:nil`；
   「排序模式」进了编辑态但没有 `canMoveRowAtIndexPath` / `moveRowAtIndexPath:` → **拖不动**。
2. **缺 2 个页面**：`account-category`（账本分类设置）、`account-import`（从母本导入，勾选树）。
3. **14 个服务方法零引用**，含 `deleteCategory`（分类删除接不上 UI）、`mergeAccounts` / `previewMerge` /
   `getCategoryCandidates` / `importCategories`（正好对应上面缺的两页）、`reorderCategories`。
4. 缺 `/statistics/category`、`/statistics/monthly`；流水页无搜索。
5. 死代码：`ABPlaceholderViewController`（零引用）、`sharedCache`、`fromDictionary`。
6. **`frontend-IOS/` 整个目录 untracked** —— 10453 行无版本控制保护。
7. **iOS 侧无任何自动化测试**，与前端（146 单测 + 74 回归 + 4 守卫脚本）是最大落差。

### 方法：怎么判一个服务方法是不是死的

`grep -rn "<方法名>" --include="*.m" --include="*.h" .` —— 若只匹配到 `.h` 声明 + `.m` 定义两行，
即零引用。

⚠️ **别用「在 Controllers/Views 里 grep」当判据** —— 会误伤走本地 Store 缓存层的方法
（`getAccounts` 就是经 `ABAccountStore` 间接调用的，直接搜 UI 层得 0，但它活得好好的）。
**要算全工程引用数，不是只搜 UI 层。**

## 十、本轮修复（同日，提交 `d8856fc`）

### 1. 分类管理页 4 个假控件 → 整页重写

原状是 `handler:nil`（搜索确定 / 批量隐藏 / 批量删除）+ `setEditing:YES` 但拖不动。

**没有走"补几个 handler"这条路**，因为三种模式会同时改变**顶栏、底栏、每行尾部控件**三处形状，
用 ActionSheet 表达不了 —— 整页按前端重写：

| 模式 | 顶栏 | 底栏 | 行尾 |
|---|---|---|---|
| 普通 | 返回 / X分类管理 / 搜索 | 排序 / 批量操作 / 新建分类 | 铅笔 |
| 批量 | 取消 / 选择X分类 / 全选 | 删除 / 隐藏 / 恢复显示 | 勾选框 |
| 排序 | 取消 / X分类排序 / 空 | 完成 | 系统拖动把手 |

排序的九条设计决定里，**D3（边缘自动滚动）/ D6（不重排、提示线）由系统提供**；
**D1 有差异**：前端是按住把手**立刻**拖动，iOS 原生是**长按 ~0.5s**。
不自己造手势是因为系统拖拽已打通重排动画与无障碍 —— 差异写在文档里，不假装对齐。

### 3. 顺带发现并修掉的 4 个真 bug

1. **「收入分类管理」进的是支出分类** —— `ABMineViewController` 里 `cat-expense` 与 `cat-income`
   创建**同一个对象**，而 `init` 硬编码 `@"expense"`。
2. **「默认账本」徽标从未显示** —— 账本管理页用 `registerClass:` + `dequeueForIndexPath:`，
   拿到的是 `Default` 样式，`detailTextLabel` **恒为 nil**。不报错、不崩溃。
3. **账本管理页整页没有 `didSelectRowAtIndexPath`** —— 点账本完全无反应，也没有分类设置入口。
4. **`init` 未重写导致集合为 nil** —— `_roots` / `_picked` 为 nil 时 `addObject` 是**静默 no-op**，
   页面永远显示空状态而数据其实早就回来了。

### 5. 三条 UI 教训（本轮实测踩到）

1. **高度归零的容器必须 `clipsToBounds`。** `searchBar` / `sortHint` 靠"高度设 0"隐藏，
   但子视图按 `centerY` 居中 → 溢出到容器上下两侧，**三个模式都在顶栏下露一条被裁半的残影**。
2. **内容撑开的容器：label 的垂直 hugging 必须提到 required。**
   `headerCard` 被拉成 **582pt**（应为 ~66），tableView 被挤到 **79pt**。
   根因**不是冲突而是约束不足** —— UILabel 的 intrinsic 高度只是 251 优先级的软约束，
   求解器有自由度去吸收剩余空间。判据：`_autolayoutTrace` 报 `AMBIGUOUS LAYOUT for UIView.Height`。
3. **BSD grep 不认 `\b` 词边界。** `grep -E "\bmethod\b"` 在 macOS 上**匹配不到任何东西**，
   会让"零引用"清单**全量误报**（实测连 `deleteCategory` 都报 0，差点据此写下错误结论）。
   用 `grep -rn "method"` 或 `grep -o "method" | wc -l`。

### 6. 验证方法：用 lldb 驱动模拟器（本轮最有价值的产出）

iOS 侧没有自动化测试，AppleScript 点击模拟器会被系统权限挡掉（`-10004`）。
可行的路子是 **lldb 附加到进程直接执行 ObjC**：

```bash
PID=$(pgrep -f "MyAccountBook.app/MyAccountBook" | head -1)
lldb -b -p $PID \
  -o 'expr -l objc++ -- (void)[(UINavigationController *)[[[UIApplication sharedApplication] keyWindow] rootViewController] pushViewController:(UIViewController *)[NSClassFromString(@"ABCategoryViewController") new] animated:NO]' \
  -o 'detach' -o 'quit'
sleep 4 && xcrun simctl io booted screenshot /tmp/shot.png
```

切模式：对 `topViewController` 发 `performSelector:@selector(onEnterBatch)` / `@selector(onEnterSort)`。

踩到的四个语法坑：

- **`[NSClassFromString(@"X") new]` 优于 `alloc + performSelector`** ——
  后者报 `no known method '-performSelector:withObject:'`（lldb 不知道自定义选择器的返回类型）。
- **取属性用 `valueForKey:`**，直接点属性名会报 "no known method"。
- **打印整数要包成 NSNumber**：`po @([[... count])`；且 `count` 前要 cast 成 `NSArray *`。
- **`_autolayoutTrace` 是查布局问题的第一手段**，比逐个数 frame 快得多。

### 2. ⚠️ 三处 size 超限 —— 三个页面全都没数据（既有 bug）

**发现路径**：验证搜索时顺手截了流水页，发现**分组展开了却没有明细行**。
→ 查 `details` 字典为空
→ 查系统日志（`xcrun simctl spawn booted log show --predicate 'process == "MyAccountBook"'`）
→ `[flow] 明细加载失败: 输入有误，请检查后重试`

根因在 `src/transaction/dto/transaction.dto.ts`：

```ts
@Rule(RuleType.number().integer().min(1).max(100).default(20))
size: number;
```

**size 上限 100。** iOS 三处超限，且请求是**整条被拒、不是截断**：

| 位置 | 原值 | 症状 |
|---|---|---|
| `ABFlowViewController` 分组明细 | 500 | 点开分组永远空白 |
| `ABCalendarViewController` 月视图 | 500 | 日历上一个数字都没有 |
| `ABExportViewController` 导出 | 10000 | 导出一直是坏的 |

修法：服务层加 `getAllTransactions:` 循环分页
（`PAGE_SIZE=100` / `MAX_PAGES=200`，退出条件抄前端 `pages/export`）。

### 3. 这次的教训

**「编译通过 / 请求发出去了 / 接口返回 200」都不代表数据到了。**
`size` 这种有上下限的数值参数必须对着后端 DTO 核一遍，而不是"填个够大的数"。

**更值得记的是发现路径**：我是为了验证搜索才顺带看见明细是空的。
**如果只验自己新写的那块，这个 bug 会一直躺在那儿。**
