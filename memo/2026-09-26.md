## 本轮做了什么

### 1. 流水页补「按分类分组」维度

前端流水页底栏是**两个维度**：时间粒度（年/季/月/周/天）+ 分类分组（level 1/2）。
iOS 侧只有前者。补了后者：

- 底栏「月 / 分类」两格切换
- `ABQueryBuilder` 加 `categorySummaryParamsWithFilter:level:accountId:`
- ⚠️ 两维度**互斥**：`time` 带 `unit` 不带 `level`；`category` 带 `level` 不带 `unit`。
  混传不报错，但对应字段被后端忽略 → 症状是「切了维度没反应」（又是静默的）。
- `ABSummaryItem` 加 `parentName`：二级口径下标题是二级名、副标题是所属一级。

**有意偏离前端**：`__none__`（未分类）组**不给展开箭头**，`willSelectRowAtIndexPath` 返回 nil。
前端这里可展开，但展开后走「按未分类过滤」—— 后端**不支持**，点了只会拿到空列表。
让无效路径不可达，比画一个点了没反应的箭头强。

### 2. 出参解析核对（结果是阴性，但值得记）

用 demo 账号逐个接口抓真实返回，把 5 类模型的键名全对了一遍：嵌套 `category`/`account`、
`__none__`、`parentName`、年度 trend —— **全部正确**，没有静默解析 bug。

阴性结果也固化：真实样例写进 `ABModelParsingTests` 当 fixture（12 条）。
后端哪天改字段名会直接红。

### 3. 测试 69 → 86

新增 `ABModelParsingTests`（12）+ `ABQueryBuilderTests` 补 15（两维度互斥）。
负向验证都做了：去掉 `order` / 去掉 size 夹取 / 分类维度混传 `unit` → 均如期变红。

## 顺手做完的下一项：删死代码（`cd68392`）

原清单写 3 个，实际**只有 2 个真死**：

| 项 | 结论 |
|---|---|
| `ABPlaceholderViewController` | 真死（"地基占位"空壳 VC），**已删** |
| `ABCache` / `sharedCache` | 真死（整个类无人 import），**已删** |
| `fromDictionary` | **假阳性，保留** —— 实际在 `ABOfflineQueue.m:95` 被调用 |

**假阳性根因**：扫描脚本判据是「出现次数 ≤ 2 即死」，而"1 次定义 + 1 次调用"的正常方法
恰好等于 2。阈值改 **≤ 1** 后重跑：服务层 47 个方法判死 **0** 个（旧阈值误报 4 个，
另三个是 `ABQueryBuilder` 的白名单辅助方法）。
→ 已沉淀为 `docs/工程约定与踩坑.md` §五 **第 20 条**。

**踩坑**：`generate_project.rb` 会 `rm -rf` 整个 `.xcodeproj`，CocoaPods 集成跟着没了，
直接编译报 `'Masonry/Masonry.h' file not found` —— **两步必须连着跑**。

验证：BUILD SUCCEEDED + 86 用例全绿。规模 63/62 → **61/60** 文件、15101 → **14957** 行。
