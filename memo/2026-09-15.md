### 折叠的实现

```ts
/** 折叠时展示的条数（与参考图一致：默认 5 条 + 「点击展开」） */
const COLLAPSED_COUNT = 5;
const expanded = ref(false);

/** 折叠态：默认只显示前 COLLAPSED_COUNT 条；展开后显示全部 */
const visibleRanking = computed(() =>
  expanded.value ? ranking.value : ranking.value.slice(0, COLLAPSED_COUNT)
);
```

模板里 `v-for` 由 `ranking` 改为 `visibleRanking`，列表末尾加：

```html
<view v-if="ranking.length > COLLAPSED_COUNT" class="rank-toggle" @click="expanded = !expanded">
  <text class="rank-toggle-text">{{ expanded ? '收起' : '点击展开' }}</text>
  <SvgIcon :name="expanded ? 'icon-chevron-up' : 'icon-chevron-down'" :size="12" />
</view>
```

与 RankList.vue（报表页用）的 `.toggle` 是**同一套做法**，交互一致。

## 修 bug：类型弹层选完回面板点「确定」被旧值覆盖（已完成）

**用户报告**：筛选弹窗确定后，选的流水类型失效、变回全选。

### 根因

`FlowFilterPanel.vue` 只用 `watch(() => props.visible)` 同步草稿，
而**类型弹层是叠在筛选面板之上的**（z-index 1100 > 1000）——
筛选面板的 `visible` 全程为 `true`，那个 watch **根本不会触发**，
`draft.types` 始终停留在打开面板那一刻的旧值（全选）。
于是「类型弹层选支出（已生效）→ 回面板 → 点确定」时，
`emit('apply', { ...draft })` 把旧的全选值**覆盖**回去。

### 修法

把 `types` 也纳入**受控同步**（与已有的「时间三件套」同一套做法）：

```ts
watch(
  () => [props.model.timeLabel, props.model.start, props.model.end, props.model.types],
  () => {
    draft.timeLabel = props.model.timeLabel;
    draft.start = props.model.start;
    draft.end = props.model.end;
    draft.types = [...(props.model.types || [])];
  },
  { deep: true }
);
```

并在注释里写明：**将来再加叠层子弹层时，把它的字段也加到这里，别指望 watch(visible)**。

### 新增验证脚本 scripts/verify-type-filter.mjs（11 项）

精确复现用户报的场景：打开面板 → 点类型 → 只选「支出」→ 弹层确定 →
**回面板再点确定** → 检查类型是否还在。

**负向验证**（项目铁律第 10 条）：临时把 `types` 从受控同步里拿掉，脚本报 **FAIL=6**
（不是静默通过），恢复后回到 **PASS=11**。

### 写脚本时暴露的第二个问题：脚本自己会卡死

第一次跑负向验证时**超时被 SIGTERM**：bug 回退后第 [4] 步判 FAIL，
脚本继续跑到第 [5] 步的 `.filter-tip-action`（此时不存在）→ Playwright 默认等 30s → 卡死，
**连统计都打不出来**。

修法两处：① `page.setDefaultTimeout(6000)`；② 提示条不存在时**跳过后续依赖它的断言**并显式记 FAIL。

> 教训：**「跑不出结论」和「跑出结论说失败」是两回事。**
> 验证脚本必须在「前置条件不成立」时也能给出结论，而不是挂在等待上。

## 流水页筛选新增「分类」，并反转「分类维度不带时间」的旧约定（已完成）

需求：筛选面板里加「分类」（参考图里它在「时间」之后），并明确「底栏『分类』只是换个展示形态，筛选条件照常生效」。

### 后端（3 处）

`summaryByCategory()` 是**裸 SQL**（不走 `applyFilters`），原先只应用 type / accountId / 关键词 / 金额区间，
**不读 start/end/categoryIds**。本次补齐：

```ts
if (query.start) { conditions.push('t.record_date >= ?'); params.push(query.start); }
if (query.end)   { conditions.push('t.record_date <= ?'); params.push(query.end); }
// categoryIds：与 applyFilters 完全同口径 —— 传一级时其下二级也要命中
if (query.categoryIds) {
  const ph = catIds.map(() => '?').join(',');
  conditions.push(`(t.category_id IN (${ph}) OR t.category_id IN (
     SELECT c2.id FROM categories c2 WHERE c2.parent_id IN (${ph})
   ))`);
  params.push(...catIds, ...catIds);
}
```

⚠️ **这是裸 SQL，没法复用 `applyFilters`，只能逐条对齐** —— 注释里写明「改 applyFilters 语义时务必回来同步这里」。

## 修 bug：分类弹层列表滑不动 + 文字穿透到「确定」按钮上（已完成）

**用户报告**：选择分类弹层里列表滑不动，字穿透到按钮上。

### 根因（MEMORY 里记过三轮的坑，我又犯了）

uni-app 的 `scroll-view` **不吃 flex 推导**，而我给两个新弹层写的是失败方案①：

```scss
.body { flex: 1; min-height: 0; }   /* ❌ scroll-view 会按内容撑开，溢出并盖住底部按钮 */
```

项目里 `flow/index.vue` 的时间弹层注释详细记过这三轮失败：

| 方案 | 症状 |
|---|---|
| `flex:1 + min-height:0` | 按内容撑开，滚轮**溢出并盖住「确定」**（点击被拦截） |
| `flex:1 + height:0` | footer 被挤出容器（整体向上溢出） |
| `height: calc(72vh - 144px)` | 依赖 max-height 精确对齐，脆 |

**最终方案（本次照做）**：高度由 **JS 按视口算**，不依赖任何 flex 推导。

### 修法（两个弹层都改）

1. `scroll-view` 加 `:style="{ height: bodyHeight + 'px' }"`
2. `bodyHeight = max(160, round(windowHeight × 0.72) − 152)`（header/footer 各 76）
3. `.sheet` 补 **`overflow: hidden`**（只写 `max-height` 时它**约束不住 flex 子项**，内容超长会直接溢出）
4. `.body` 由 `flex: 1; min-height: 0` 改为 **`flex: none`**
5. `FlowTypePicker.vue` 补 `ref` 导入（新增 `windowHeight` 用到）

> `FlowTypePicker` 目前只有 2 项、看不出问题，但**同结构同样脆**，一并修。

### 验证脚本补了布局断言（第 [7] 段，5 项）

- 滚动区高度确定（>0）
- **量的是分类弹层（88 行），不是筛选面板**
- 滚动内容确实可滚（`scrollHeight > clientHeight`）
- 「确定」按钮完整可见（不超出 sheet 也不超出视口）
- **滚动区底部不越过「确定」按钮顶部**（正是用户报的穿透）

### 写断言时又踩一个坑：类名重名导致量错元素

第一版 `document.querySelector('.body')` 量到的**是筛选面板**（`childCount=5`，正是它的 5 行），
因为**筛选面板与弹层用了同一套类名**（`.sheet` / `.body` / `.btn-confirm`），且筛选面板在 DOM 中更靠前。
于是断言 `scrollHeight > clientHeight` 报 FAIL（253 > 253）—— **看起来像布局没修好，实际是量错了元素**。

修法：断言里限定 `document.querySelectorAll('.sheet')` 的**最后一个**，
并**新增一条断言专门盯这件事**（`bodyChildCount === 88`）—— 否则下次还会量错。
