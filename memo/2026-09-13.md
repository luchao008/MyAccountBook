## 单页容器的滚动位置记忆（已完成）

昨天把 4 个 Tab 页折叠成单页容器（`pages/main/index.vue`）后，切换视图会回到顶部。
本次补上**各视图独立记忆滚动位置**。

### 实现要点

- 位置表用**普通对象**而非 ref：`onPageScroll` 触发极频繁，
  走响应式等于每次滚动都推一次依赖，而这里不需要响应式。
- **恢复期间暂停记录**（`restoring` 标志）—— 这是唯一容易踩的坑：
  切换视图时页面总高从「旧视图高度」突变成「新视图高度」，浏览器会立刻调整
  scrollTop，这个中间态同样触发 `onPageScroll`；不禁用就会把它写进**新视图**
  的位置表，污染真实记忆。
- 恢复动作放 `nextTick` 后再 `setTimeout(0)`：v-show 切换后高度由新视图决定，
  在高度更新前滚动会被旧高度截断。
- `pageScrollTo` 的 `complete` 部分端不回调 → 另设 120ms 兜底解除 `restoring`，
  否则它会永久卡住，导致位置再也不被记录。

### 验证

`build:h5` 通过；配色 155 项全绿；dev 200。

**手动验证**：明细页滚到中部 → 切首页 → 切回明细，应停在原位置。

### 这一节的重点是"两次实测打脸"

写死在 CSS 里的注释全是错的，是量出来才发现：

| 版本 | 实测 | 症状 |
|---|---|---|
| ① `min-height: 56px` | `barHeight = 79`、`overhang = −1` | 凸起项内容（48+2+17+10）**把底栏一起撑高**，圆被整个吞进底栏 |
| ② 改 `height: 56px` | `btnH = 25` | 高度固定后内容是"溢出"态，而 **flex 子项默认 `flex-shrink: 1`**，48px 的圆被压成药丸 |
| ③ `height: 56px` + `flex-shrink: 0` | `overhang = 22` ✓ | 圆的 48×48、越出 22px、凸起项文字与其它项差 1px |

**两条通则**（都是这次踩出来的）：
1. **`min-height` 挡不住内容撑高容器** —— 要让某个子项"越出"父容器，父容器高度必须写死，
   否则它一定被最高的子项撑开，"凸出"就永远不发生。
2. **溢出 ≠ 禁收缩**。固定父高之后，子项进入溢出状态，flex 会先把它压扁（`flex-shrink: 1`），
   尺寸写死 48px 也没用，必须显式 `flex-shrink: 0`。

底栏 56px（原 52）+ 凸出 22 = 顶端 78px，各视图留白 88px 仍够，未改。

**颜色说明**：参考图的圆是浅橙，本项目用 `$brand-600 #CF4A12`（白加号 4.52:1 ✅）。
`$brand-500 #FF6B35` 上压白字只有 2.84:1，不能用于承载白字 —— 这是既有的品牌色分档规则，未破例。

## 两个 bug 修复（用户报告）

### ① 内容不足一屏也有滚动条

**根因（实测，非推测）**：uni-app H5 把页面内容放在 `uni-page-wrapper` 里，其高度 =
`100vh − 导航栏(44px)`。而页面里写的是 `min-height: 100vh` —— 把导航栏那 44px
**多算了一遍**，于是**每个这样的页面恒溢出 44px，与内容多少无关**。

`scripts/diagnose-scroll.mjs` 的实测数据完全对得上：

| 页面 | 内容区高 | `.page` 的 min-height | 溢出 |
|---|---|---|---|
| statistics / mine / 账本选择页 | 768 | 812 | **恰好 44px** |
| home / detail | 768 | 812 | 143 / 165（这两页内容本来就超屏，该滚） |

**修法**：收敛成一个 token，全项目 **10 处**替换：

```scss
// tokens.scss
$page-min-height: calc(100vh - var(--window-top, 0px) - var(--window-bottom, 0px));
```

`--window-top` 是 uni-app 自己暴露的（实测值 `calc(44px + 0px)`），
所以 `navigationStyle: custom` 的页面会自动退化成 `100vh`，不需要特判。

修复后：statistics / mine / 账本选择页 **44 → 0**；home / detail 仍滚（内容确实超屏）✓

### ② 分类删除的提示文案错了两处，而且方向相反

`pages/category/index.vue` 把子分类数**当参数从模板传**，两处都传错：

- 删一级分类传 `onDelete(root, 0)` → **硬编码 0**，
  "该分类下还有 N 个二级分类，会一并删除"这句**永远不出现**
- 删二级分类传 `childrenOf(root.id).length` → 这是**它的兄弟数量**，
  于是删一个二级却提示"该分类下还有 7 个二级分类会一并删除"

**修法**：子分类数改为在函数里自己算 ——

```ts
function onDelete(item: CategoryItem) {
  const childCount = childrenOf(item.id).length;   // 从数据算，不靠调用方传
```

**消除"调用方可以传错"这个入口**，而不是把两处值改对（后者下次还会错）。

验证：`scripts/verify-category-delete.mjs`（打开弹窗读文案，**只读不删**，一律点取消），
四项断言全过。实测：一级「居家物业」→「该分类下还有 7 个二级分类，会一并删除；…」（与页面角标 7 一致）；
二级「公共交通」→ 只有「相关账单会变为「未分类」。确定删除「公共交通」？」。

用户最初说的是 vue-icons，但调研发现 **`vue-icons` 的两个候选包
（`@kalimahapps/vue-icons` / `vue-icons-lib`）收录的全是单色线性图标集**，
做不出参考图的彩色效果。用户确认要彩色后，方案定为：

- 数据来源：Iconify 的离线图标集包（devDependency，不进产物）
  - `@iconify-json/flat-color-icons` 329 个扁平彩色（48 网格）→「多彩」Tab
  - `@iconify-json/noto` 精选 141 个（128 网格）→「生活」Tab
  - 「标准」Tab 复用项目原有的 `CATEGORY_ICONS`（单色，15 个）
- 生成脚本 `scripts/gen-color-icons.mjs` → `frontend/src/constants/color-icons.ts`
- 渲染组件 `components/ColorIcon.vue`（多色）+ `components/CategoryIcon.vue`（自动选渲染器）

**为什么不直接引运行时库**：项目已有「图标数据内置 + 自绘组件」的模式
（`constants/icons.ts` + `SvgIcon.vue`）。再引一个运行时库等于两套体系并存，
且只有被选中的图标需要进产物（noto 全量 3800 个，我们只要 141 个）。
生成脚本留在项目里 ⇒ 这份数据是**可复现**的，不是一次性粘贴。

体积：源文件 632 KB / **gzip 212 KB**（懒加载的二级页面，可接受）。

### 三个坑（都是实测出来的）

1. **noto 的 SVG id 会撞车**（生成期必须处理）
   noto 大量使用 `<linearGradient id="svgIDa">` + `fill="url(#svgIDa)"`。
   这些 id 在各自文件里唯一，但**放到同一页面就重复了** —— 浏览器解析 `url(#id)`
   取的是文档中第一个同 id 元素，于是第 2 个及之后的图标会拿到第 1 个图标的渐变，
   **颜色整体错乱**。图标选择器一屏要渲染几十个，必然触发。
   修法：生成时给每个 id 加集合前缀（`colorful-` / `life-`），同时替换 `url(#…)` 引用。

2. **flex 容器用 `min-height` 会把固定底栏顶出屏幕**
   图标选择页写 `.page { min-height: $page-min-height; display:flex; flex-direction:column }`，
   `.grid { flex: 1 }`、`.tabs { flex: none }`。结果**底部 Tab 整条不见了**（截图才看出来）：
   `min-height` 下容器高度是 auto，`flex: 1` 的子项按**内容高度**撑开，把 Tab 推到了屏幕外。
   修法：改 `height: $page-min-height` —— 内部靠 scroll-view 滚动的页面，容器需要**确定高度**。

3. **uni-app H5 里 `.input` 不是 `<input>`**
   写测试脚本时 `page.locator('.input').fill()` 会报
   "Element is not an `<input>`" —— uni-app 把它渲染成 `<uni-input>` 外壳 + 内部真 input。
   选择器要写成 `.input input` 穿透一层。

## 底栏「明细」改为「报表」并改成跳转（明细下线、统计独立成页）

### 需求与拍板

需求：底栏「明细」改名「报表」，点击**不切换视图、改为页面跳转**。
项目里原本**没有「报表」这个页面**（设计文档 §7 页面清单是 首页/明细/统计/我的/记一笔），

- **报表落点 → 把统计拆成独立页**（`pages/statistics/index`），底栏那一格叫「报表」
- **明细去留 → 退出底栏并下线**（动手前先核查引用：全库只有容器自己引用 `DetailView`，
  首页/我的都没有指向明细的入口 → **下线后交易流水全应用没有任何入口**，此后果已明确报告）

### 关键实现：TabBar 的 item 级 url

要让某一格「跳转」而不是「切视图」，给 item 加 `url` 即可，**两种模式都成立**。
`go()` 里 url 分支必须排在受控模式判断**之前** —— 反过来的话跨页项会被当成容器里并不存在的
视图 `emit`，父级没有对应分支 → **点了没反应且不报错（死按钮）**。

于是底栏一格有两种语义：**无 url = 切视图，有 url = 离开本页**；判断只看 url 不看模式。
默认项 5 格 → 4 格（记账 / 报表 / 记一笔 / 我的）；容器只剩 **记账 / 我的** 两个视图。

### 三处顺带纠正的判断

1. **`--view-bottom-gap` 的默认值要等于事实**。`StatisticsView` 的底栏留白原写死 88px，
   但它现在只被独立页承载（无底栏）→ 改为 `var(--view-bottom-gap, 0px)`。
   默认值写错方向时，忘记设的代价是「页底一片空白」（容易被忽略），而不是「内容贴底」（一眼可见）。
2. **报表页刻意不带底栏**：导航模式的底栏靠 `navigateBack` 回栈，而它**不会重跑 `onLoad`**，
   `?tab=` 不生效 —— 想让它能切「记账 / 我的」得另设计，不能直接套导航模式。
3. **底栏 4 格时凸起项几何上无法居中**（实测落在 62.5%，偏移 46px ≈ 底栏宽 12.3%）：
   3 个视图 + 1 个动作时槽位中点是 12.5/37.5/62.5/87.5%，要居中必须左右同宽 = 5 格。
   这是信息结构决定的，不是样式没调好。
