## 实现要点

- 右侧 `scroll-view` 加 `@scroll` 监听 + `scroll-into-view` 定位；
  每个分组设锚点 id（`group-anchor-<rootId>`），左侧 `side-anchor-<rootId>`。
- **锚点测量**：`uni.createSelectorQuery().in(getCurrentInstance())`，
  取各分组与滚动容器的 `boundingClientRect`，相减得到相对内容顶部的偏移
  ——该值不随滚动变化，**只需在弹窗打开后测一次**。
- **滚动反推**：`scrollTop >= anchorTops[i] - 8`（8px 容差防边界跳动），
  取满足条件的最大 i 作为当前组。
- **双向定位都要"先清空再赋值"**：`scroll-into-view` 值不变不会重新触发滚动，
  必须 `mainIntoView=''; nextTick(() => mainIntoView='group-anchor-x')`。
- 左栏跟随高亮项滚动（同样用 scroll-into-view）。
- 搜索模式切到独立结果列表（不做联动），退出搜索后重新测量。

## 踩坑

## 补充：滚动条——左侧隐藏、右侧自绘贴边

用户反馈：右侧滚动条被 `.main` 的 `padding: 12px` 挤进了内容区，不在最右侧。
**根因**：原生滚动条永远贴"滚动容器"的边缘，而 padding 在容器内侧，
所以只要容器有右 padding，滚动条就不可能贴到组件最右侧。

**解法：放弃原生滚动条，自绘**：

- `onMainScroll` 里本来就有 `scrollTop`，顺手记下 `scrollHeight`；
  `measureAnchors` 时顺便量出可视高度——三者齐了就能算滑块位置：
  `barHeight = viewport/scrollHeight * viewport`（最小 40px），
  `barTop = scrollTop / scrollable * (viewport - barHeight)`。
- 滑块是 `.content` 下的绝对定位元素（`right: 2px`），不受 `.main` 的 padding 影响。
- `pointer-events: none` —— 纯位置指示器，不拦截滚动手势。
- 原生滚动条沿用 App.vue 的全局隐藏规则（正好避免出现两根）。
- 加了 `transition: top 0.08s linear`，滑块移动更顺滑。

教训：**和框架内部 DOM 结构斗争不如换思路**。第一版试图用 CSS 选择器
精确命中 uni-scroll-view 的内层容器来"恢复"原生滚动条，位置不可控；
改为自绘后位置完全由自己的布局决定，反而更简单。

## 移动端配色与字体规范（已完成，仅规范不含组件改造）

用户要求「仅针对移动端优化界面设计，聚焦配色与字体」。产出：

### 体检结论（都是实测，不是目测）

| 发现 | 数据 |
|---|---|
| 裸色值 | 全 `src/` 40+ 个，「同义不同值的灰」5 个 |
| `uni.scss` 变量引用次数 | **0** —— 有 token 文件，但没人用 |
| 对比度不达标 | **9 处**；最严重是白字压主色按钮 `#FF6B35`（2.84:1） |
| 字体文件 | 无（唯一的 `.ttf` 是 uni-ui 图标字体）——现状正确，别加 |

### 方案要点

- **品牌橙拆三档**：`#FF6B35` 只做装饰/Logo/图表（白字 2.84 不达标）→ 按钮底 `#CF4A12`（4.52 ✅）
  → 橙色文字/Tab/焦点环 `#C7430F`（4.95 ✅）。品牌识别靠色相，换明度几乎看不出。
- **9 处修复**：收入 `#52C41A→#0B8038`、支出 `#FF4D4F→#D92D20`、辅助 `#999→#6E7787`、
  链接 `#4A90D9→#1D63B8`、Tab 两色、按钮底。
- **图表 8 色换 7 色**：原调色板的 `#7ED321`(青柠) 与 `#50E3C2`(薄荷) 色盲下几乎同色；
  新序列用 Okabe-Ito 色相做底、贪心优化 + 人工选色相家族，**相邻段色盲可区分度最低 75.0**（阈值 70）。
  配套要求：扇区 2px 白色描边 + 图例含名称/金额/占比 + 最多 7 段（Top6 + 其他）。
- **字体**：系统字体栈（不引中文 Web 字体）；八档 12/14/15/16/17/20/28/36 px，**11px 全部抬到 12px**；
  字重只用 400/500/600（禁 700，CJK 伪粗体会糊）；行高正文 1.6。
- **等宽数字**：金额加 `font-variant-numeric: tabular-nums` + 右对齐 —— 记账 App 的关键细节。

### 踩坑 / 发现

- **优化器不会审美**：纯贪心最大化色盲距离，结果产出「两个洋红 + 两个天蓝」，功能合格观感灾难。
  最终做法是**人工挑色相家族、脚本只做验收**。
- **第一版图表配色自我否决**：品牌橙 `#C2410C` 与琥珀 `#B45309` 色盲距离仅 11.7（同一个颜色）。
- **文档里写数字前必须实测**：我一度在文档里写「`#0B8038` 压浅绿底只有 4.1:1」，实跑是 **4.52:1**；
  反倒是 `#D92D20` 压浅红底 4.22、`#C7430F` 压浅橙底 4.49（都差一点不达标）。
  **"背景一变，前景必须重算"** —— 这直接催生了独立的徽标色 token。
- **SCSS 块注释会进产物**：用 `/* */` 写 token 注释，编译后 3.6KB 注释原样打进 CSS；
  改 `//` 后产物 1 字节。校验方式：`npx sass tokens.scss out.css && wc -c out.css`。
- **验证 token 文件的方式有点特别**：它只有变量和 mixin，正确产物就是**空文件**，所以"能编译"不够，
  还得写探针 `.scss` 实际消费一遍变量与 mixin 才能证明可用。
