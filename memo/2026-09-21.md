## 二、为什么从 bridge 改成 host

**问题**：bridge 模式下即使把端口映射写成 `[::]:8080:80` 双绑，
群晖上外网 IPv6 仍可能访问不通 —— 因为 **bridge 模式的 IPv6 取决于
Docker daemon 是否开启 IPv6**，而群晖默认常常没开。

**方案**：改 `network_mode: host`，容器直接共享宿主网络栈 →
群晖的 IPv6 地址 / 防火墙规则**直接生效**，IPv4/IPv6 由宿主机统一决定。

**代价**：端口即宿主端口，无映射；需自行保证端口不冲突。

## 三、最终网络拓扑（docker-compose.nas.yml）

| 服务 | 网络 | 端口 | 对外 | 说明 |
|---|---|---|---|---|
| web | host | **8082** | ✅ IPv4+IPv6 | App 前端 nginx |
| admin | host | **8081** | ✅ IPv4+IPv6 | 中台 nginx |
| backend | host | 7001 | ❌ 仅回环 | `HOST=127.0.0.1` |
| db | host | 3306 | ❌ 仅回环 | `--bind-address=127.0.0.1` |

- web/admin 的 nginx：`listen 8082` + `listen [::]:8082`（admin 同理 8081）；
  `proxy_pass http://127.0.0.1:7001`（host 网络下不再是服务名 backend）
- backend：`DB_HOST=127.0.0.1`（不再是 db）、`HOST=127.0.0.1`（仅回环监听）
- db：`command: --bind-address=127.0.0.1`

**安全设计**：对外只开 8082/8081；backend(7001)、db(3306) 都只绑回环，
外网碰不到 —— 这是 luchao 明确要求的（选 B 方案）。

  已核对 Midway koa 源码：`hostname` 会传给 `server.listen({ host })`。

## 八、NAS 部署步骤（本次）

```bash
cd /volume1/docker/account-book
docker load -i backend.tar && docker load -i frontend.tar && docker load -i admin.tar
docker compose -f docker-compose.nas.yml down   # 网络模式变了，必须重建
docker compose -f docker-compose.nas.yml up -d
```

访问：App `http://NAS_IP:8082`、中台 `http://NAS_IP:8081`（IPv6 同理）。

## 九、注意

- **端口冲突**：host 模式下 8082/8081/7001/3306 都是宿主端口，
  确保没被占用（冲突时改 nginx `listen` + compose 注释 + 重建镜像）。
- **`down` 别加 `-v`**：否则删 db 数据卷（数据在
  `/volume1/docker/account-book/data` bind mount，不受影响，但仍谨慎）。
- **db 限回环**：只有本机能连 3306；若之前用别的机器连过，将连不上。
