## 一、审计脚本基线（`scripts/audit-h5-bundle.mjs`）

新增的产物体积/关键路径校验器。`--budget` 模式可接 CI，超预算或懒加载回归 → 退出码 1。

**基线（干净构建 `frontend/dist/build/h5`，gzip level 9）**

| 项 | gz | raw |
|---|---|---|
| `index.html` | 2.8 KB | 5.4 KB |
| 入口 chunk `index-*.js` | **103.2 KB** | 295.4 KB |
| 全局 CSS `uni.*.css` | 4.3 KB | 21.7 KB |
| 全局 CSS `index-*.css` | 3.2 KB | 10.9 KB |
| **关键路径合计** | **113.5 KB** | 333.4 KB |

- 入口 chunk 是**自包含**的（0 条静态 import）→ Vue + uni-h5 runtime + 页面懒加载表都在里面。
- 按需块：`constants-color-icons` 206.6 KB gz、`components-TrendChart` 67.6 KB gz、
  `uni_modules/…/echarts.min.js` 243.5 KB gz（**从不被请求**）。
- 43 个 JS chunk，页面 chunk 都只有 3~8 KB gz。
- 预算：入口 120 / 关键路径 160 / 单 chunk 140 KB（= 实测 + 一成余量，目的是**拦恶化**）。
- 守卫：`constants-color-icons` 与 `components-TrendChart` 一旦进登录页/主页面的 `__vite__mapDeps` → FAIL。

**负向验证（都跑过，不是"应该能报错"）**
1. `--entry-budget=1` → FAIL + 退出码 1；
2. 合成产物把 `constants-color-icons` 的下标写进 `pages-login-index` 的依赖表 → FAIL + 退出码 1；
3. ⚠️ **合成产物第一次没红**：fixture 写成 `import(...),M=__vite__mapDeps(...)`，
   与 vite 真实产物（中间无赋值）不一致 → 正则失配 → 被"解不出依赖名单"分支兜住、报告照样通过。
   两处因此改掉：fixture 改成同形；**「解不出依赖名单」从 WARN 升级为 FAIL**。
   —— 又一次"判据看着覆盖了、实际被兜底分支吃掉"。

### 3.3 一个操作教训：dev server **冷启动会让探针假红**

**4.4 的判据已查清**（省下一轮重复调研）：
- `luch-request` **没有原生重试**（`src/lib/` 下 `grep retry` 零命中）；
- 它的 `settle()` 在**传输层失败**（断网/超时）时同样 `reject(response)`，此时
  **`response.statusCode === undefined`** ⇒ 判据：**只重试 `!error?.statusCode` 且 method 是 GET**；
- 有 `statusCode` 的 4xx/5xx 一律不重试（对端明确拒绝，重试没意义）；
- POST 新增流水**可以**重试（有 `clientId` 幂等键）—— 这个理由要写进注释，别让人以为是通用的。
