## iOS 风格 UI 样板（本轮新增，状态：待用户确认）

**背景**：用户要求「先了解项目现状 → 设计一套贴近苹果 iOS 的设计样板（配色/字体/圆角/间距/图标/阴影/动效）→ 确认后再逐页面改造」。

### 现状体检结论（实测，非估计）

- 技术栈 uni-app + Vue 3 + SCSS；**15 页面 / 22 组件 / 31 功能图标**
- 现有语言 FL-1「数字优先·通栏扁平」：页面底=卡片=`#FFFFFF`，靠发丝线分区；
  全项目 `box-shadow` 仅 **6 处**（2 处还是 inset/transition），`backdrop-filter` **0 处**
- **图标是零成本项**：现有 31 个图标本来就是 SF Symbols 画法（24 栅格 / 1.75px 描边 / round / currentColor），不用重画
- **字号阶梯也是零成本项**：现有 36/28/20/17/16/15/14/12 与 iOS 的 34/28/20/17/17/15/13/12 高度重合

### 最重要的实测发现：iOS 系统色几乎全部不过 AA

| 系统色 | 压白卡 | |
|---|---|---|
| `#007AFF` 蓝 | 4.02 | ❌ |
| `#34C759` 绿 | 2.22 | ❌ |
| `#5856D6` 靛 | 5.65 | ✅ **唯一达标** |
| `#FF9500` 橙 | 2.20 | ❌ |
| `#30B0C7` 青 | 2.57 | ❌ |
| `#8A8A8E` 次级灰 | 3.44 | ❌（Apple 自己的次级文字色也不达标） |

→ **结论：形取 iOS，色值不照抄。** 保留原生值作图形填充，另配一套 AA 校准值作文字/按钮。

### 三条关键设计决策

1. **`#0060DF` 一个值打通"蓝字"与"白字按钮"** —— 洞察是**对比度是对称的**（白底蓝字 5.62 == 蓝底白字 5.62），
   所以不需要像原来品牌橙那样拆两档。**token 数减半，改造面随之减半。**
2. **收入红 `#D92D20` 压 iOS 灰底从 4.83 跌到 4.33** → 不改色值，改为硬性约束「**收支金额只能落白卡/白行**」。
   在 iOS 分组列表里这条天然成立（每行都是白载体），实现时是顺势不是负担。
3. **不做 iOS 26 Liquid Glass**：`backdrop-filter` 在小程序端支持度参差、低端 Android 掉帧，
   改用 iOS 17–18 式半透明 + 毛玻璃（含 `@supports` 降级）。

### 可复用的方法（值得沉淀）

**从参考截图提取设计规范**的采样三步法，本次一次成型：

1. **高频色统计**（`Counter` 降采样）→ 背景/卡片/主色/文字
2. **整行浅色像素占比扫描** → 找出所有横线及其精确色值与厚度
3. **按色相条件筛查 + y 分段** → 定位强调色元素（下划线、强调线、图标底色）

⚠️ 坑：`sed -i ''` 在 zsh 下会失败；改用 Python 做文件内替换更可靠。
⚠️ 坑：Ardot 里 `I()` 的 binding 名混入西里尔字母（`NV2rс`）会被静默跳过该行，用纯 ASCII 命名。
⚠️ 坑（本轮踩了两次）：**给已有容器改 `layout` 时必须同时重设 `width`/`height`** ——
否则尺寸 fallback 成 FIXED 并裁掉内容（实测卡片区被锁死在 100px，内容整块消失）。
**`M()` 之后子节点的 `fill_container` 也不会自动重算**，要沿容器链重写一遍宽度。
**跨 op 引用新节点必须用 binding 名**：写错字面 ID 会把节点移到别的父级下，且只报一条 `parent not found`。

### 5. 图表序列重排（用户选定"整套按参考图重排"）

**参考图实测**：环形图**青绿主导**（`#56C4C5` 占 29609px），另有蓝 `#5F8EF4` /
紫 `#6F54F4` / 橙 `#F5862D`。
**但 4 个色里 2 个连 3:1 都不到**（青绿 2.08、橙 2.52）→ **只能借色相骨架，色值必须重配**。

**踩到的坑**：按参考图色相顺序直接排，闭环最小可区分度只有 **10~16** ——
因为这些色相**全挤在冷区**（青 185° / 蓝 213° / 紫 251°），色盲下几乎同色。
而原项目序列是**冷暖交替**排的，所以有 90.15。

**两个关键洞察（值得复用）**：
1. **闭环序列的"旋转"不改变相邻关系** —— 末位与首位相接，转一圈相邻对完全相同。
   所以把青绿从第 4 位转到首位，可区分度**一分不损**。
2. 但「其他」必须固定第 7 位（前端 `MAX_SLICES = 6` 截断），简单旋转会破坏它。
   → 固定「首 = 青绿、末 = 灰」，中间 5 个**全排列枚举**（120 种），最优解 **73.63**。

**最终序列**（只改 **1 个色值** + 重排）：

```
#0E7C86 青绿 / #7c3aed 紫 / #0e7c42 翠绿 / #c2185b 品红 / #1d63b8 蓝 / #c2410c 橙红 / #8a94a6 灰
```

- 闭环最小 **73.63**（阈值 70，**余量仅 3.63**）
- 前 6 色压白 **4.95–5.95**，都能当白字底
- 代价：90.15 → 73.63（重排的代价，记录在案）

### 6. 深色模式品牌金（我推荐，用户采纳）

亮色金 `#A85F12` 压 `#1C1C1E` 只有 **3.49**（跌破）→ 必须单独配一个值。
选 **`#E4AD77`**（8.54 页面底 / 7.00 卡片），让品牌金在亮/暗下形成一对
（`#A85F12` ↔ `#E4AD77`），与 iOS 把 `#007AFF` 提到 `#0A84FF` 是同一个做法。

**一个有价值的对称**：`#E4AD77` 在**亮色**下只能做图形（压白卡 1.99），

### 阶段 0 抓到并修掉的一个真红灯（重要）

首次跑回归是 **PASS=63 / FAIL=9**，9 条同一根因：

> **账本级分类改造（09-16）后 `accountId` 成为分类接口必传参数，而回归脚本没跟上。**

| 失败项 | 表面返回 | 真因 |
|---|---|---|
| `valid token 200` / `list 200` / `filter by type 200` | 422 | `/api/categories` 缺 `accountId` |
| `dup name 409` / `update 200` | 422 / 404 | 同上 |
| `delete missing 404` | 400 | **默认账本分类禁删（D16）先于「不存在」判定** |
| `type mismatch 400` / `category filter 200` | 200 / 422 | 交易没带 `accountId`，落到默认账本 |
| `cross-user category 404` | 400 | 跨用户断言没带自己的 accountId |

**修法**（`scripts/regression-test.sh`，本阶段唯一改动的代码文件）：

1. 「token 有效性」探针 `/api/categories` → **`/api/accounts`**（前者现在必传 accountId，当探针本身就错）
2. `[category]` 段先建 **`copyAll:false` + 空 categoryIds 的临时非默认账本**，分类用例全在它上面跑
   （默认账本禁删分类，用它验不出「删不存在分类应 404」）
3. `[transaction]` 段的交易补 `accountId`，与所用 `categoryId` **同账本**
4. **新增 2 条不变量断言**：`missing accountId 422`、`category from other account 404`
5. 跨用户隔离断言补上「用自己的 accountId 去读别人的分类」

**结果：PASS=74 / FAIL=0**（72 → 74，净增 2 条）。
