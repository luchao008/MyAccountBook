## 0. 给执行者的三条铁律

### 铁律一：顺序不可颠倒

```
阶段 0 冻结基线 → 阶段 1 建基础设施 → 阶段 2 样板屏（决策门）
   → 阶段 3 列表页 → 阶段 4 表单页 → 阶段 5 全局收口
```

**尤其不能颠倒的一条**：`check-contrast.mjs` 的断言基线**必须在代码改完之后**才改。
先改脚本会让守卫失效（详见 §6.2 第 4 条）。

### 铁律二：每阶段有退出条件，未满足不得进入下一阶段

每个阶段的末尾都有一行 **`▶ 退出条件`**，它是一条可执行命令 + 期望输出。
**跑不过就不要往下做** —— 带着未验收的债务往前走，后一阶段的所有判断都会失真。

### 铁律三：做机械操作时，必须「全局搜索 + 回读确认」

本项目的改造是**全量替换色值**，而同一个色值会散落在几十个文件里。
只改第一眼看到的那处 = 制造新的不一致。具体做法见 §6.3 第 1 条。

## 2. 风格方向

### 2.1 一句话

> **形取 iOS，色值重校准**：iOS 的层级语言（分组背景、白卡片、发丝线、大标题、毛玻璃、克制阴影）全部照搬；
> iOS 的系统色值**一个都不照抄**（9 个系统色里 8 个不过 WCAG AA），改用经 AA 校准的暖金 + 青绿。

### 2.2 视觉规范（执行时只需这一张表）

**阴影（五档，三档是零）**

| Token | 值 | 用途 |
|---|---|---|
| `none` | — | **默认**。列表、卡片、单元格全部零阴影 |
| `card` | `0 1px 2px rgba(0,0,0,.04)` | 独立卡片脱离背景时 |

**导航栏标题：两种形态，按「是不是一级目的地」分**（执行阶段 3 时实测确认的规则）

| 页面类型 | 形态 | 已用于 |
|---|---|---|
| **一级目的地**（能从底栏直达） | **Large Title**：返回行 + 左对齐大标题（`$font-display` 28/36 + 600） | 报表 |
| **深层页**（从列表 / 表单 push 进来） | 紧凑居中标题（`$font-h2` 17/24 + 600） | 分类管理、数据导出、登录、账本管理等 |
| **自定义 Hero 头** | 不用标题行，渐变头本身承担 | 首页、流水 |

> 大标题**只用 `$font-display`（28/36），不要写 30/38** —— 字阶是固定 8 档，
> 阶梯外的 `font-size` 会被 `check-contrast.mjs` §13 判成 MISMATCH。
> ⚠️ 别为了「统一」把深层页也改成大标题：iOS 本身就是这么分的，深层页用大标题反而占掉一屏内容。

### 2.3 交互与动效

| 场景 | 规格 |
|---|---|
| 列表行按下 | 底色转 `#F5F5F5`，100ms ease-out 变色、200ms 回弹，**无位移** |
| 按钮按下 | `scale(0.97)` + 底色降为 `#8F5312`，120ms ease-out，抬手立即回弹 |
| Tab 视图切换 | 250ms ease-out，**只做淡入，禁止横滑**（项目已实现，保持） |
| 页面 push / pop | 300ms `cubic-bezier(.32,.72,0,1)`，进出并行 |
| 底部 Sheet | 上滑 400ms `cubic-bezier(.32,.72,0,1)`，遮罩 200ms 同步淡入 |
| 金额变化 / 成功反馈 | 500ms `cubic-bezier(.34,1.56,.64,1)` 弹簧回弹，**必须配等宽数字防抖** |
| 减弱动态 | `prefers-reduced-motion` 下全部压到 `0.01ms`，只保留透明度变化 |

**动效上下限**：低于 200ms 感受不到反馈，高于 400ms 会焦躁。**弹簧曲线只给「确认成功」用**，常规交互不许用。

### 2.4 毛玻璃材质（顶栏 / 底栏）

```scss
background: rgba(249, 249, 249, 0.72);
backdrop-filter: saturate(180%) blur(20px);
-webkit-backdrop-filter: saturate(180%) blur(20px);

// ⚠️ 降级必须写，否则部分机型是纯透明一片
@supports not ((backdrop-filter: blur(1px)) or (-webkit-backdrop-filter: blur(1px))) {
  background: rgba(249, 249, 249, 0.96);
}
```

- **不做** iOS 26 Liquid Glass：重度依赖多层 `backdrop-filter` + 高光描边，小程序端支持度参差、低端 Android 掉帧。
- 小程序端 `backdrop-filter` 支持度不稳，**直接走实色分支**。
- 滚动时导航栏下方不留硬阴影，只在底边画 1px `#F1F1F1`（滚动态才出现）。

## 6. 约束条件与红线

### 6.1 绝对不能动的（业务侧）

| 红线 | 原因 |
|---|---|
| 任何 API 契约、请求参数、响应字段 | 本次是**纯视觉改造** |
| 两级分类口径（叶子分组 + JS 按 `parentId ?? leafId` 归并） | 刻意设计，改样式时别碰 |
| 报表两个 Tab 各自记忆时段（基础当年 / 分类当月） | 刻意设计，粒度不同是**有意的** |
| 排序 `record_date DESC, record_time DESC, id DESC` | 接口契约 |
| 流水页吸顶变色阈值 | **必须实测，不许硬编码** |
| 日历 swiper 复位 + 前缀和二分 | 性能关键路径 |
| TabBar 凸起项的排列序号 | 居中依赖「排第几」 |
| `$success` / `$danger` 语义 token | 与收支语义不同，不许混用 |
| 金额的 `tabular-nums` + 右对齐 + 带正负号 | 颜色不得作为唯一区分手段（WCAG 1.4.1） |

### 6.2 工程化约束

1. **改完必须跑工程化三件套**（lint / 类型 / 格式），有既有告警也顺手修掉。

2. **`tokens.scss` 改完必须重启 dev server** —— `scss.additionalData` 只在启动时读一次。

3. **两个真源必须同步**：`constants/chart.ts` 与 `tokens.scss` 的 `$chart-series` 是双写，改色时两处都要动。

4. **`check-contrast.mjs` 的基线不能在阶段 5 之前改。**
   它守卫的是**代码的当前状态**，不是设计意图。提前改成 v1.1 的值会得到最糟的状态：**脚本一直红、代码一行没改** → 于是没人再跑它，守卫作用归零。
   正确顺序：**设计定稿 → 改代码 → 改断言 → 跑通**。
   （`check-ios-tokens.mjs` 不存在这个问题 —— 它守卫的是「设计规范」，与代码无关，可随时更新。）

5. **`reflow-audit.mjs` 的真实缺口是「弹层等交互态扫不到」**，不是「新组件」。
   它按 URL 扫 DOM，页面在清单里、新组件就会被自动扫到。
   但它**不会去点开**：记一笔的数字键盘、流水页的 5 个弹层、三列滚轮 —— 而这些恰恰是 v1.1 改动最集中的地方。**必须人工补验。**

6. **新增的校验断言必须做一次负向验证**：故意改错 → 确认报错且退出码非 0 → 改回来。
   **没验过「能报错」的校验器等于没有校验器。**

### 6.3 六个反复咬人的坑（必须按此做）

1. **同一概念的所有出现位置必须全局搜一遍。**
   只改第一眼那处 = 制造新的不一致。
   - ⚠️ Bash 的 `grep` 对中文不可靠（假阴性），中文检索用 **Grep 工具**
   - ⚠️ 裸搜 `frontend/` 会因 `node_modules` 超时，要限定 `frontend/src`
   - 色值替换用「行号 + 整行内容」双断言的脚本，**别只靠 grep 定位**（无 `#hex` 的样式行 grep 不到）

2. **同一文件的多处修改必须串行。**
   并行发两个针对同一文件的 `Edit` 会**静默丢改动**（两个都报 success）。改完回读确认。

3. **会改动 DOM 的测量脚本，读和写必须分两趟。**
   边遍历边写内联 `font-size` 会逐层复利（实测同一元素 60→120→240px）。

4. **验证脚本必须自建前置条件**，不能假设库 / 页面干净。
   同一 URL 连续巡检时 **hash 变更不重新挂载组件**；跨页巡检每次显式 `page.reload()`。

5. **判断「是否溢出」不能用 `scrollWidth`**（见 §5.3）。

6. **布局约束四条**：
   - `flex: 1` 等价 `flex: 1 1 0%`，带 `flex-wrap` 的行里是陷阱 → 要留空间写 **`flex: 1 1 auto`**
   - flex 项默认 `min-width: auto`，是顶破容器最常见原因 → 显式 **`min-width: 0`**
   - 固定宽度一律改 **`min-width`**
   - `flex-wrap: wrap` 在「本来放得下」时是 no-op，给现有行加它是安全的兜底

### 6.4 平台差异（uni-app，会静默出错）

| 陷阱 | 表现 | 正解 |
|---|---|---|
| **SVG 里不能写 `<text>`** | 模板里的 `<text>` 被编译成 `<uni-text>`，SVG 不认识 → **文字完全不渲染且不报错** | 文字走 **HTML 覆盖层** |
| `<text>` 渲成 inline `<span>` | `text-overflow: ellipsis` 不生效，加 `overflow:hidden` 会被**静默裁掉** | 让内容足够短（`shortMoney` 分档） |
| `scroll-view` 不吃 flex 推导 | `flex:1 + min-height:0` / `flex:1 + height:0` 都失败 | **必须给确定高度，由 JS 按视口算** |
| `scroll-view` 的 `scrollTop` 是受控值 | 脚本里 `el.scrollTop = N` 会被回写重置 | 用**真实滚轮手势**（`page.mouse.wheel`）或 `window.scrollTo` |
| `box-sizing: border-box` + 固定 height + `padding-bottom: env()` | 内容被挤扁（实测 `.tab-item` 55 → 21） | **height 也跟着安全区长**（`calc(56px + env(...))`），并先写不带 env 的兜底 |
| uni-ui 组件的 `$uni-*` | 在自己块内重声明且不带 `!default`，覆盖本项目赋值 | 库限制，**别再「修」** |
| `pages.json` easycom | `qiun-data-charts` 必须显式加 `^qiun-data-charts$` | 默认 `autoscan` 覆盖不到，会报 `Failed to resolve component` |

### 6.5 什么时候必须停下来问人

执行者**只在这四种情况下**暂停并提问；其余情况一律按本计划执行：

1. 本计划与 `docs/UI设计方案·iOS风格样板.md` **冲突**（以本计划为准，但要报备）
2. 改动需要**触碰 §6.1 红线中的任一项**（例如发现不改业务逻辑就实现不了）
3. 验收命令出现**本计划未列举的失败**，且无法在 2 次迭代内解决
4. 遇到**需要审美判断**的新场景（例如某页出现设计规范里没有的控件）

**不要**因为以下理由停下来：不确定色值（表里有）、不确定顺序（§3 有）、不确定是否要动逻辑（不动）。
