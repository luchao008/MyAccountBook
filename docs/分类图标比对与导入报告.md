## 一、扫描概况

| 项 | 结果 |
|---|---|
| 文件数 | 75（扩展名全部为 `.svg`，无 PNG/ICO/其他格式） |
| 实际格式 | 每个 SVG 是「**2048×2048 JPEG 图片 base64 内嵌**」的包装文件（`<image href="data:...">`），并非矢量路径 |
| ⚠️ MIME 标注 | 数据头写的是 `data:image/png`，实际数据是 JPEG（`/9j/` 魔数）——浏览器按内容嗅探可解码，但体积不可接受 |
| 背景 | **纯白底（255,255,255），无透明通道** |
| 体积 | 单文件 307–492 KB，合计 **39 MB** |
| 文件名 | 全部为中文分类名（如 `午餐.svg`），与项目预置分类命名体系同源 |

项目内所有"有名字的图标"分三类，逐一比对结果：

## 六、导入与优化结果

| 项 | 结果 |
|---|---|
| 原始文件备份 | `assets/cat-icons-original/`（75 个 SVG，39 MB，不进构建产物） |
| 应用内资源 | `frontend/src/static/cat-icons/`（75 张 **256×256 透明 PNG**，合计 3.9 MB） |
| 优化处理 | 缩放 2048→256 + **四边泛洪填充去白底转透明**（内部白色高光保留）——由 `scripts/gen-cat-icons.mjs` 生成，可复现 |
| ⚠️ 文件名 | 产物文件名是**拼音**（`午餐.svg` → `wucan.png`）：uni-app H5 dev server 的静态中间件不解码 URL，中文名文件在开发环境必然 404 并回退成 index.html（实测）；生产 nginx 无此问题，但为保证开发/验证环境可用，统一 ASCII |
| 引用方式 | `<image src="/static/cat-icons/<拼音>.png">`，按需 HTTP 加载；key 仍是 `img:<中文分类名>` |
| 构建影响 | `dist/build/h5` 从约 2.4 MB 增至约 6.5 MB（+4.1 MB，仅图标） |
