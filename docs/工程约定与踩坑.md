## 一、实现约定

### 1.1 数据与接口（只记会静默出错的）

- **金额全程字符串**（`"12.34"`）；**ID 是 BIGINT → 字符串**（别用 `===` 比数字）。
- **改外键字段时，实体上已加载的关系对象要一起改**，否则 TypeORM 会回填旧值（踩过 3 次）。
- **TypeORM raw query 不支持 `:name` 命名参数**，必须 `?` + 数组。
- **SQL 别名别用保留字**（`key` 在 MariaDB 直接语法错误 → 500），用 `groupKey`。
- **路由顺序**：`GET /transactions/summary` 必须在 `GET /transactions/:id` **之前**注册。
- **列表与汇总共用同一套筛选**（后端模块级 `applyFilters()`）。分类多选传**一级会连带命中其下二级**。
- `src/` 下的脚本**不要无条件自执行**（Midway 扫描器会加载它，会把服务带走）。
- 本地调试 curl 必须 `--noproxy '*'`，否则被 127.0.0.1:7897 代理拦成 502。

### 1.2 颜色与字体（改界面前必读）

- **v1.1 有效值**：分隔线 `#F1F1F1` · 页面底 `#F8F8F8` · 卡片**零描边** + 圆角 16 ·
  文字 `#222226` / `#6B6B72` / `#9A9AA0`（仅装饰）· 主色金 **`#A85F12`**（图形金 `#E4AD77` 配白字仅 1.99）·
  青绿 `#56C4C5` 图形 / `#2E9496` 大字 / `#0E7375` 小字。
- **语义色**：收入 `#D92D20`（红）、支出 **`#0F7B7C`（青绿）** —— 2026-09-16 v1.1 定案（原 `#0B8038`）。
  `$success`/`$danger` **不动**（语义不同）。投资模块若新增须另建 `market-up`/`market-down`。
- **改任何颜色都要重算对比度。背景一变，前景必须重算** —— 本项目已发作**四次**。
- **文字禁用 `opacity`**（白字 4.52 × 0.85 只剩 3.69）。要"次要"就换 token。
- **最小字号 12px**；字重只用 400/500/600（**禁 700**，CJK 伪粗体）。
- 金额一律 `font-variant-numeric: tabular-nums` + 右对齐 + 带正负号（色不单独承担语义）。
- **uni-ui 的 `$uni-*` 在自己块内重声明且不带 `!default`**，会覆盖本项目赋值
  （唯一生效的是带 `!default` 的 `uni-easyinput.$uni-border-1`）。库限制，别再"修"。
- 批量改色用「行号 + 整行内容」双断言的脚本，**别只靠 grep 定位**（无 `#hex` 的样式行 grep 不到）。
- ⚠️ **调色板缺口（无解）**：没有「能压白卡被看见 **且** 金字保持 4.5:1」的浅金表面
  （`$v11-gold-soft` 压白卡仅 1.07）→ **浅金底只能作氛围，必须再给一条金色细边**才成为「可点表面」
  （分类选中 / 日期「今天」/ 回收站「恢复」）。**删掉那些边 = 选中态直接消失。**

### 1.3 重排（320px / 200% 字号）

- **`flex: 1` 等价 `flex: 1 1 0%`**。带 `flex-wrap` 的行里是陷阱：basis 为 0 意味着"它认为这栏不需要空间"
  → 该换行的不换。**要留空间写 `flex: 1 1 auto`。**
- **flex 项默认 `min-width: auto`**，是顶破容器最常见原因 → 显式 `min-width: 0`。
- **固定宽度一律改 `min-width`**（`width:56px` / `width:18px` 这类都在大字号下卡出盒子）。
- **`flex-wrap: wrap` 在"本来放得下"时是 no-op**，是安全兜底。反之写 `min-width: 5em` 这类阈值
  **必须先用容器真实内宽核过**（我算成 288px，实际只有 260px）。

### 1.4 溢出的真实形态（验收方法）

本项目"溢出"**不表现为滚动条**：uni-app 给 `body` 加了全局 `overflow-x: hidden`，横向滚动条**永不出现**。
两种真实形态：①被祖先 `overflow:hidden` **裁掉**；②宽于自身盒子但与邻居**重叠压字**。
**这两种 `document.scrollWidth` 都测不到** —— "scrollWidth 没超标"绝不能作为验收依据。
`reflow-audit` 已知盲区：测不到**文字压在同一盒子内的装饰图形上**（环形图中心注解的约束是内孔 132px，
而非容器 180px）。**"没报"不等于"没问题"。** 它**不模拟 safe-area**，那类 bug 靠 `verify-safe-area.mjs` 抓。

### 1.5 uni-app 平台的静默陷阱

- **SVG 里不能写 `<text>`**：被编译成 `<uni-text>`，SVG 不认识 → **文字完全不渲染且不报错**。
  正解是文字走 **HTML 覆盖层**。**build / vue-tsc 全绿对这类静默空白毫无作用。**
- **`<text>` 被渲成 inline `<span>`，`text-overflow: ellipsis` 不生效** → 加 `overflow:hidden` 的结果是
  **被静默裁掉**。正解：让内容足够短（`shortMoney` 分档）。
- **`box-sizing: border-box` + 固定 `height` + `padding-bottom: env(safe-area-inset-bottom)` 会把内容挤扁**
  （实测 `.tab-item` 从 55 塌到 21）。**正解：height 也跟着安全区长**，并**先写不带 env 的 height 作兜底**。
- **`scroll-view` 不吃 flex 推导**（`flex:1+min-height:0` / `flex:1+height:0` 都失败），**必须给确定高度**。
- **`scroll-view` 的 `scrollTop` 是受控值**（脚本里赋值会被回写重置）→ 测滚动必须用**真实滚轮手势**。
- **`box-sizing` / `z-index` 类改动要同时看"被盖住的元素是否仍拦截点击"**。
- ⚠️ 用 `write` 工具写验证脚本会把 `\d` 转义成 `d`（正则失效致假失败），**用 heredoc 写**。
- ⚠️ `scripts/**/*.mjs` 是**双执行上下文**（主体跑 Node，`page.evaluate()` 回调跑浏览器）。
  `eslint.config.mjs` 里的 `document`/`window`/`location`/`history`/`localStorage`/`getComputedStyle`/`getCurrentPages`
  这 8 个全局缺一个就整片 `no-undef`。

### 1.6 只记「会静默出错」的页面约定

- **流水页**：⚠️ 切分组维度要**同时改 `unit` 和 `groupBy`**。弹层**贴屏幕底边升起、不留底栏高度**（有意）。
  `.nav` 吸顶：**渐变头高度必须实测**（写过 180 而实测 146 → 白图标压白页面）；搜索框展开会改变头高，**要重测**。
- **流水全屏搜索**：金额搜索 SQL 必须 `CAST(t.amount AS CHAR) LIKE :kw`（`t.amount LIKE` 匹配不到小数）。
  验证"搜索页内无分组"要限定在 `.search-page` 内（主列表 `.group` 仍在 DOM 里）。
- **`utils/period.ts`** 的「分组键 ↔ 日期区间」**必须与后端 `GROUP_FORMAT` 完全一致**（week 是 **ISO 周**）。
- **记一笔默认时刻**：**提交时**取 `new Date()`。⚠️ 必须单独存 `userClearedTime`
  （"没选过"与"主动关掉开关"都是 `null`，靠值分不开）。
- **主容器底栏 3 格**：⚠️ **凸起项居中取决于"它排第几"**（3 格时槽中心 16.7% / **50%** / 83.3%）。
- **`reflow-audit.mjs` / `diagnose-scroll.mjs` 的页面清单必须随结构变化同步**：失效的 `?tab=xxx`
  **不报错、会静默落到首页**（量的是首页却记为那个视图 = 假全绿）。

### 1.7 自绘顶栏的横向几何（2026-09-17 新增）

**约定**：自绘顶栏的返回行统一 `.nav-inner { padding: 0 $space-2 }`（**8px**）。
现有 5 个自绘顶栏页：流水 / 日历 / 回收站 / 数据导出 / **报表**。
（报表页原先漏了这层 padding，触摸区顶到视口左边缘 `x=0`，2026-09-17 已修。）

⚠️ **陷阱：`svg` 包围盒左边缘 ≠ 箭头的可见墨迹左边缘。**
`icon-chevron-left` 在 24 视口里只占中段，缩到 20px 后墨迹还要再内缩 **5.94px**
（≈ `size × 0.297`）。所以：

```
墨迹位置 = 触摸区起点 + 图标在按钮内的偏移 + 内缩（20px 图标 ≈ 5.94px）
```

**这条推出一个反直觉的结论**：想「给行加 padding 让返回键远离边缘」，
必须**在按钮内部把等量位移补回来**，否则墨迹会被一起推右。
实测：`padding: 0 8px`（行）+ `justify-content: flex-start; padding-left: 4px`（按钮）
→ `8 + 4 = 12`，正好等于原来的 `0 + (44-20)/2 = 12` → **墨迹不动，只有触摸区右移**。
只加行 padding 就会把墨迹推到 25.94，同时偏离大标题与参考图（见下）。

**那 12px 是在对齐谁**：不是手感 —— 参考图 `IMG_4201`（iPhone 16 Pro @3x）实测箭头墨迹
**17.0pt**。所以 `12` 这个数只服务一件事：**让箭头墨迹停在 17.94px**。
（2026-09-17 上午写这条时的理由是"与报表页左对齐大标题同轴"；当日下午大标题被收进顶栏，
**理由作废、数值不动** —— 它本来就由参考图定，不由标题定。）

**验收方式（可复现）**：`node scripts/verify-topbar.mjs`（25 项断言，含负向验证）。
它用 `getBBox()` 量墨迹，而不是 `getBoundingClientRect()` 量包围盒 ——
后者会给出"差 4px"的假信号，据此去改会把本来对齐的东西推歪。

⚠️ **5 个页面的墨迹目前不统一，而且理由已经失效**（下表为脚本实测值）：

| 页面 | 触摸区左边缘 | 箭头**墨迹**左边缘 | 按钮内对齐 |
|---|---|---|---|
| 流水 / 日历 / 回收站 / 数据导出 | 8 | **25.94** | `justify-content: center` |
| **报表** | 8 | **17.94** | `flex-start` + `padding-left: 4px` |

统一的是**触摸区**（都是 8）；差 **8px** 的是**墨迹**。报表页那 17.94 原本靠两条理由撑着 ——
「与它那 28px 左对齐大标题（16px）同轴」+ 参考图 17.0pt；大标题 2026-09-17 收进顶栏后
**只剩参考图一条**。是否统一（把 4px 补偿推广到 5 个页面）**待决定**，见 `memo/2026-09-17.md` §十。

### 1.8 顶栏标题：绝对定位居中，**必须**配 `pointer-events: none`（2026-09-17 新增）

报表页标题从「返回行 + 左对齐 28px 大标题」收进那 44px 返回行（luchao 要求）：
标题 `$font-h2`(17/24) + 600、**居中**，吸顶区 **137px → 89px**（44 顶栏 + 45 Tab）。

⚠️ **别用 `.nav-title { flex: 1; text-align: center }`**（流水页 / 分类页的写法）：
那是在**剩余空间**里居中，不是**在屏幕里**居中。左侧 44px 返回键、右侧为空
→ 文字中心比屏幕中心**右偏 (44+8)/2 = 26px**。宽标题不明显，「报表」两个字一眼能看出。
正解是绝对定位（`left/right: 0` + `text-align: center`），这也是 iOS 的做法。

⚠️ **`pointer-events: none` 不是可选优化，是必需项**：绝对定位的标题横跨整行、
且晚于返回键绘制，漏掉它就**整块吃掉返回键的 44×44 触摸区** ——
页面照常渲染、标题照常显示，只有点下去没反应，**肉眼完全看不出来**。
同类漏法：忘了给 `.nav-inner` 加 `position: relative`，标题会相对更外层定位，换宽度就飘。

两条都已进守卫（`check-ios-tokens.mjs` §14，共 **112 项**断言；两条都做过负向验证 ——
删任一条 → 退出码 1 并打印出违规文件）。

**验收方式（可复现）**：`node scripts/verify-topbar.mjs`（25 项断言）。它用
`document.elementFromPoint()` 在返回键触摸区的**左上 / 中心 / 右下**三点做命中测试，
断言都落在返回键内 —— 只量几何是查不出「被盖住」的（`getBoundingClientRect` 完全正常）。

**负向验证过，且结果正是"三点都要量"的理由**：删掉 `pointer-events: none` 后，
只有**中间那一点**报 `MISS(uni-text)`，左上与右下两点仍然 `back` ——
**只量一个点就会漏掉这个 bug**。

## 二、账本级分类（2026-09-16 起，重大变更）

分类从「用户级共享」改为「**账本级隔离**」，详见 `docs/账本级分类设计文档.md`。
`categories.account_id`（NOT NULL，FK CASCADE），唯一键 `(account_id, name)`。

- **默认账本 = 母本**：新建账本的候选分类来自它；**它的分类不允许删除**（40006）；
  删默认账本时新默认账本会从 preset 重建全套 89 个。
- **两道保护**：分类下**有交易**（未软删）禁删 → 40004；默认账本分类禁删 → 40006。
- **核心不变量**：交易的 category_id 所指分类，必须与交易同 account_id。
- **合并账本**：分类**按 name 匹配**；去重指纹用**分类名**而非 id。
- **前端**：`categoryStore` 绑定当前账本（切账本自动重载）；新增页 `account-new`/`account-category`/`account-import`。
- **`copyAll`**：`POST /accounts` 默认 true；false 时按 `categoryIds`（**空数组 = 一个都不要**，与不传不同）。
- **踩过的坑**（都已修 + 有回归）：软删除交易未过滤 / 空数组被当「全选」/ DTO 加了 `.required()` 拦掉空数组。

## 三、本地启动

| 服务 | 命令 | 端口 |
|---|---|---|
| 数据库 | `docker start account-book-mariadb` | 3306 |
| 后端 | `npm run dev`（= `mw dev --ts`） | 7001 |
| 前端 | `cd frontend && npm run dev:h5` | 5173（vite 代理 `/api` → 7001） |

- 命令前需 `export PATH=/usr/local/bin:$PATH`；登录 `demo` / `123456`。
- **长驻进程必须用工具的 `run_in_background`**，`nohup ... &` 起的会被杀掉。
- ⚠️ **不要给 dev server 挂管道**（`| tail`）—— 管道退出会带走进程。用 `> /tmp/x.log 2>&1`。
- **`vite.config.ts` 的 `host: '0.0.0.0'` + `strictPort: true`**。**判断服务可用要分别探 `127.0.0.1` 和
  `localhost`**，只探一个会被"localhost 只监听 IPv6"骗过。

## 四、已知未决

- **顶部安全区未处理（全站性，2026-09-17 实测）**：`index.html` 的 viewport 在 iOS 下会带
  `viewport-fit=cover`，而 `env(safe-area-inset-top)` 源码里**一处都没用**（底部却用了 21 处）；
  同时 H5 的 `uni.getSystemInfoSync().statusBarHeight` **恒为 0**（实测内联 `padding-top: 0px`）。
  → 结论：**在带刘海/灵动岛的真机上，5 个自绘顶栏页（含报表）的返回行会落在状态栏区域里**。
  浏览器里看不出来（Safari 自己的 chrome 占着顶部），所以一直没暴露。
  修法待定：给自绘顶栏补 `padding-top: max(env(safe-area-inset-top), <原 statusBarHeight 逻辑>)`，
  但需真机复验「Safari 收起工具栏时会不会多出一段空白」。**未做。**
- **CORS 未配**（靠 Vite 代理 + 生产同域反代）。
- **【已知接受】环形图中心注解在大字号下与环带重叠**：内孔 132px，`¥13918.05` 在 ×2 字号下需 198px，
  **几何上无解**。同一金额在汇总卡已可读。
- **键盘 Tab 导航未打通**（uni-app H5 把 `<view>` 渲成不可聚焦元素，需加 `tabindex`）。
- **分类拖动排序未做**（拖不动的手柄等于骗用户）。
- **「明细」下线后交易流水在全应用无入口**（09-13 luchao 要求）。若恢复建议做**独立页**再挂入口。
- **`pages/account-select` 的 `--view-bottom-gap: 52px` 与实际底栏 56px 差 4px**。
- **P2 池**：分类改名/换图标入口、删除回收站、骨架屏、分类拖动排序。
- 库里存在测试残留账号（4 个分类数异常），属测试产物。
