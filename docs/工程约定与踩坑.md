## 一、实现约定

### 1.1 数据与接口（只记会静默出错的）

- **金额全程字符串**（`"12.34"`）；**ID 是 BIGINT → 字符串**（别用 `===` 比数字）。
- **改外键字段时，实体上已加载的关系对象要一起改**，否则 TypeORM 会回填旧值（踩过 **4** 次）。
  ⚠️ **"改成 null" 和 "改成另一个非空值" 是同一件事的两半，只修一半等于没修。**
  2026-09-30 实例：`transaction.service.ts` 的 `update()` 里 `categoryId` 分支只处理了
  「清空分类」（`entity.category = null`），**漏了「改成另一个分类」** → 接口 200、
  返回体也是 200 看着正常（其实是旧值），库里根本没变。
  用户的感受就是「**流水编辑改了分类，保存不生效**」。
  判据：`update` 里凡 `patch.xxxId = ...`，必须同行跟着 `entity.xxx = <新实体>`；
  写完**加一条"从一个值改成另一个值"的单测**（只有"改成 null"的用例是抓不住的 ——
  这就是本次能藏这么久的原因）。
- **TypeORM raw query 不支持 `:name` 命名参数**，必须 `?` + 数组。
- **SQL 别名别用保留字**（`key` 在 MariaDB 直接语法错误 → 500），用 `groupKey`。
- **路由顺序**：`GET /transactions/summary` 必须在 `GET /transactions/:id` **之前**注册。
- **列表与汇总共用同一套筛选**（后端模块级 `applyFilters()`）。分类多选传**一级会连带命中其下二级**。
- `src/` 下的脚本**不要无条件自执行**（Midway 扫描器会加载它，会把服务带走）。
- 本地调试 curl 必须 `--noproxy '*'`，否则被 127.0.0.1:7897 代理拦成 502。
- ⚠️ **luch-request 的签名是 `delete(url, data, options)` —— 第二个参数是「请求体」，不是 axios 那种 config。**
  `http.delete(url, { params: {...} })` 里的 `params` 会被当成 **body** 发走（还是 JSON 体），
  URL 上根本没有查询串 → 后端读 query 的 DTO 报 `"xxx" 是必须的`（422 / 40000）。
  **查询串一律自己拼进 URL**：``http.delete(`/accounts/${id}?confirmName=${encodeURIComponent(name)}`)``。
  （2026-09-17 用户报「删除账本，名字输对了却提示没拿到名称」，根因就是这个。
  自仓库初始化起就存在，一直没被发现是因为它**表现成后端校验失败**，看着像后端的问题。）
  同类但**合法**的写法：`http.get(url, { params })` —— 那里 `{ params }` 落在 options 位置，别一起"修"错。

### 1.2 颜色与字体（改界面前必读）

- **v1.1 有效值**：分隔线 `#F1F1F1` · 页面底 `#F8F8F8` · 卡片**零描边** + 圆角 16 ·
  文字 `#222226` / `#6B6B72` / `#9A9AA0`（仅装饰）· 主色金 **`#A85F12`**（图形金 `#E4AD77` 配白字仅 1.99）·
  青绿 `#56C4C5` 图形 / `#2E9496` 大字 / `#0E7375` 小字。
- **语义色**：收入 `#D92D20`（红）、支出 **`#0F7B7C`（青绿）** —— 2026-09-16 v1.1 定案（原 `#0B8038`）。
  `$success`/`$danger` **不动**（语义不同）。投资模块若新增须另建 `market-up`/`market-down`。
- **改任何颜色都要重算对比度。背景一变，前景必须重算** —— 本项目已发作**四次**。
- **文字禁用 `opacity`**（白字 4.52 × 0.85 只剩 3.69）。要"次要"就换 token。
- **最小字号 12px**；字重只用 400/500/600（**禁 700**，CJK 伪粗体）。
- 金额一律 `font-variant-numeric: tabular-nums` + 右对齐 + 带正负号（色不单独承担语义）。
- **uni-ui 的 `$uni-*` 在自己块内重声明且不带 `!default`**，会覆盖本项目赋值
  （唯一生效的是带 `!default` 的 `uni-easyinput.$uni-border-1`）。库限制，别再"修"。
- 批量改色用「行号 + 整行内容」双断言的脚本，**别只靠 grep 定位**（无 `#hex` 的样式行 grep 不到）。
- ⚠️ **调色板缺口（无解）**：没有「能压白卡被看见 **且** 金字保持 4.5:1」的浅金表面
  （`$v11-gold-soft` 压白卡仅 1.07）→ **浅金底只能作氛围，必须再给一条金色细边**才成为「可点表面」
  （分类选中 / 日期「今天」/ 回收站「恢复」）。**删掉那些边 = 选中态直接消失。**

### 1.3 重排（320px / 200% 字号）

- **`flex: 1` 等价 `flex: 1 1 0%`**。带 `flex-wrap` 的行里是陷阱：basis 为 0 意味着"它认为这栏不需要空间"
  → 该换行的不换。**要留空间写 `flex: 1 1 auto`。**
- **flex 项默认 `min-width: auto`**，是顶破容器最常见原因 → 显式 `min-width: 0`。
- **固定宽度一律改 `min-width`**（`width:56px` / `width:18px` 这类都在大字号下卡出盒子）。
- **`flex-wrap: wrap` 在"本来放得下"时是 no-op**，是安全兜底。反之写 `min-width: 5em` 这类阈值
  **必须先用容器真实内宽核过**（我算成 288px，实际只有 260px）。

### 1.4 溢出的真实形态（验收方法）

本项目"溢出"**不表现为滚动条**：uni-app 给 `body` 加了全局 `overflow-x: hidden`，横向滚动条**永不出现**。
两种真实形态：①被祖先 `overflow:hidden` **裁掉**；②宽于自身盒子但与邻居**重叠压字**。
**这两种 `document.scrollWidth` 都测不到** —— "scrollWidth 没超标"绝不能作为验收依据。
`reflow-audit` 已知盲区：测不到**文字压在同一盒子内的装饰图形上**（环形图中心注解的约束是内孔 132px，
而非容器 180px）。**"没报"不等于"没问题"。** 它**不模拟 safe-area**，那类 bug 靠 `verify-safe-area.mjs` 抓。

### 1.5 uni-app 平台的静默陷阱

- **SVG 里不能写 `<text>`**：被编译成 `<uni-text>`，SVG 不认识 → **文字完全不渲染且不报错**。
  正解是文字走 **HTML 覆盖层**。**build / vue-tsc 全绿对这类静默空白毫无作用。**
- **`<text>` 被渲成 inline `<span>`，`text-overflow: ellipsis` 不生效** → 加 `overflow:hidden` 的结果是
  **被静默裁掉**。正解：让内容足够短（`shortMoney` 分档）。
- **`box-sizing: border-box` + 固定 `height` + `padding-bottom: env(safe-area-inset-bottom)` 会把内容挤扁**
  （实测 `.tab-item` 从 55 塌到 21）。**正解：height 也跟着安全区长**，并**先写不带 env 的 height 作兜底**。
- **`scroll-view` 不吃 flex 推导**（`flex:1+min-height:0` / `flex:1+height:0` 都失败），**必须给确定高度**。
- **`scroll-view` 的 `scrollTop` 是受控值**（脚本里赋值会被回写重置）→ 测滚动必须用**真实滚轮手势**。
- ⚠️ **H5 浏览器里根本不发 `touch` 事件**：只绑 `@touchstart/@touchmove` 的拖拽交互，
  在桌面浏览器（鼠标 / 触控板）下**一点反应都没有** —— 看起来像"功能没实现"，
  其实是事件压根没进来。2026-09-30 图表页转盘实测踩到。
  **修法：同时绑 `@mousedown`，并把 `mousemove` / `mouseup` 挂到 `document`**
  （指针拖出元素范围还要继续跟手；用元素自身监听会中途断掉）。
- ⚠️ **移动端拖拽还要 `touch-action: none`**：不写的话浏览器把"拖动"判定成
  **页面滚动手势**，`touchmove` 直接不派发给我 —— 同一段代码在桌面端正常、手机端失效。
- ⚠️ **uni-app H5 的页面滚动容器不是 `window` / `uni-page-body`**：实测 `document.scrollingElement`
  （`<html>`）的 `scrollTop` 才动。探针脚本里写死 `uni-page-body.scrollTop` 会一直读 0，
  但页面其实滚了 —— **"读不到滚动量"不等于"没滚动"**（别拿它当断言，否则是假红）。
- **`box-sizing` / `z-index` 类改动要同时看"被盖住的元素是否仍拦截点击"**。
- ⚠️ 用 `write` 工具写验证脚本会把 `\d` 转义成 `d`（正则失效致假失败），**用 heredoc 写**。
- ⚠️ `scripts/**/*.mjs` 是**双执行上下文**（主体跑 Node，`page.evaluate()` 回调跑浏览器）。
  `eslint.config.mjs` 里的 `document`/`window`/`location`/`history`/`localStorage`/`getComputedStyle`/`getCurrentPages`
  这 8 个全局缺一个就整片 `no-undef`。

### 1.6 只记「会静默出错」的页面约定

- **流水页**：⚠️ 切分组维度要**同时改 `unit` 和 `groupBy`**。弹层**贴屏幕底边升起、不留底栏高度**（有意）。
  `.nav` 吸顶：**渐变头高度必须实测**（写过 180 而实测 146 → 白图标压白页面）；搜索框展开会改变头高，**要重测**。
- **流水全屏搜索**：金额搜索 SQL 必须 `CAST(t.amount AS CHAR) LIKE :kw`（`t.amount LIKE` 匹配不到小数）。
  验证"搜索页内无分组"要限定在 `.search-page` 内（主列表 `.group` 仍在 DOM 里）。
- **`utils/period.ts`** 的「分组键 ↔ 日期区间」**必须与后端 `GROUP_FORMAT` 完全一致**（week 是 **ISO 周**）。
- **记一笔默认时刻**：**提交时**取 `new Date()`。⚠️ 必须单独存 `userClearedTime`
  （"没选过"与"主动关掉开关"都是 `null`，靠值分不开）。
- **记一笔表达式行不用 `direction: rtl`**（2026-09-30 luchao 定，推翻了 09-26 的写法）：
  rtl 本意是让溢出从左侧截断（尾部最新输入永远可见），但 `+`/`-` 是**中性字符**，
  在 rtl 上下文里会被重排到整串左端，表达式读起来是乱的。取舍：**顺序正确 > 尾部可见**，
  超长时改右侧截断。别"顺手加回来"。
- **流水页日头（`.day-head-text`）在分类维度必须带月份**：分类维度的组头是分类名，
  明细跨月，`13日 周一` 看不出是哪个月 → 传 `dayHeader(date, groupBy === 'category')`。
  时间维度组头已含月份，保持不带（否则重复）。
- **主容器底栏 3 格**：⚠️ **凸起项居中取决于"它排第几"**（3 格时槽中心 16.7% / **50%** / 83.3%）。
- **`reflow-audit.mjs` / `diagnose-scroll.mjs` 的页面清单必须随结构变化同步**：失效的 `?tab=xxx`
  **不报错、会静默落到首页**（量的是首页却记为那个视图 = 假全绿）。
- **图表页**（`pages/charts/index`，2026-09-30 新增）：
  · **入口在首页 banner 右上角**（`.banner-action`，包裹原有的装饰 svg `icon-chart-bar`），
    **不是顶栏按钮** —— 首页刻意保留原生导航栏（见 §1.7）。
  · **数据源用 `GET /transactions/summary?groupBy=category`**，不是 `/statistics/report` ——
    本页时间粒度是任意的（全部/天/周/季/自定义），而 report 只吃 `YYYY` / `YYYY-MM`。
    `level`(1/2) + `type`(income/expense) 正好对应四种口径（分类支出 / 分类收入 / 二级支出 / 二级收入），
    **后端零改动**。粒度→区间的换算在 `utils/period.ts` 的 `granularityRange()`（周必须用 ISO 周）。
  · **饼图是「转盘」**：白色三角**固定在 6 点方向**（`.ring-pointer`），环用**外层 CSS transform**
    旋转（`.ring-rotator`，这样吸附才能走 transition —— SVG 的 `transform` **属性**做不了过渡）。
    松手**吸附**到"选中扇区中心正对三角"，否则"指到扇区哪儿都算选中"，用户不知道该看哪。
    ⚠️ 中心「总计」必须画在旋转层**外面**（`.ring-total`），否则会跟着环一起转。
    ⚠️ 吸附要取**与当前角最接近的等价角**（±360 的整数倍），直接 `mod360` 会让浏览器反向转一大圈。
  · **条形图**：`.total-block` 滚动后缩小吸顶，`top` = **状态栏 + 44**（写死 44 会被顶栏盖住）；
    左右用负 margin 撑满屏幕宽（luchao 要求）；每行上下 padding **20px**。
  · ⚠️ 「未分类」（`key === '__none__'`）**不可点** —— 后端没有按未分类筛选的能力，
    跳过去看到的是"不带分类筛选的全部流水"（与首页排行同一约定）。
- **`NavDropdown.vue`**（顶栏下拉菜单，2026-09-30 新增）：从**触发点往下展开**，
  与"贴底升起的 sheet"是两种语义 —— 触发点在顶部就从顶部掉下来。
  展开用 `transform-origin: top` + `scaleY` 动画（`height: auto` 不可动画）。
- **引入原生 `<picker>` 必须把 z-index 抬**整组**（2026-09-30 踩了两次）**：
  uni 的 picker 默认 999，会被项目自绘遮罩（`.mask` = 1000）**整层盖住 → 点都点不到**，
  且**没有任何报错**。
  ⚠️ **只抬外层 `.uni-picker-custom` 不够** —— 实测它的 DOM 是三层，
  **真正画日历面板的是最里层的 `.uni-picker-container`**，它自己还是 999 → 依旧被盖住。
  所以 `App.vue` 的 3000 组里现在带上了
  `uni-picker` / `.uni-picker-toggle` / `.uni-picker-custom` / `.uni-picker-container` /
  `.uni-date-select` / `.uni-picker-mask` **六个**。
  **判据也要落在最里层**：探针只断言 `.uni-picker-custom` 会漏掉这个 bug（`verify-charts` 已钉住）。
  ⚠️ 另外页面里有两个 `<picker>`（起止各一）→ **会渲染两份 `.uni-picker-container`**，
  其中一份是 `display:none`、高度 0；脚本 `querySelector` 拿到它会得到"高度 0"的假失败，
  必须挑**可见的那一份**（`height > 0`）。
  **以后引入任何内置组件（picker / actionsheet / modal）先确认它在不在那一组里。**

### 1.7 自绘顶栏的横向几何（2026-09-17 新增）

**约定**：自绘顶栏的动作行统一 `.nav-inner { padding: 0 $space-2 }`（**8px**）。
现有 **6** 个自绘顶栏页：流水 / 日历 / 回收站 / 数据导出 / 报表 / **图表页**（2026-09-30 新增）。

⚠️ **首页（`pages/main/index`）刻意保持原生导航栏**：`navigationStyle: custom` 在 H5 下
确实能加自定义按钮，但 luchao 2026-09-30 定的是「不要动顶栏，直接把 banner 右上角那个
本来就有的装饰 svg（`.banner-deco`）变成入口」。所以首页**不是**自绘顶栏页，
它的图表入口在 `.banner-action`（触摸区 44，用负 margin 收回 28 的视觉占位）。

⚠️ **带交互的自绘顶栏标题不能用 `pointer-events: none`**：那条约定针对的是"纯展示的
居中标题会挡住右侧动作键"。图表页的标题**本身可点**（弹口径下拉），所以它改用
`left: 50%; transform: translateX(-50%)` 居中 —— 同样是"在屏幕里居中"，
但**宽度只占内容**，不会横铺过去压住左侧返回键。
若图省事写成 `left: 0; right: 0` 又不挂穿透，标题层会盖住返回键 → **返回键点不动**。
（报表页原先漏了这层 padding，触摸区顶到视口左边缘 `x=0`，2026-09-17 已修。）

⚠️ **陷阱：`svg` 包围盒左边缘 ≠ 箭头的可见墨迹左边缘。**
`icon-chevron-left` 在 24 视口里只占中段，缩到 20px 后墨迹还要再内缩 **5.94px**
（≈ `size × 0.297`）。所以：

```
墨迹位置 = 触摸区起点 + 图标在按钮内的偏移 + 内缩（20px 图标 ≈ 5.94px）
```

**这条推出一个反直觉的结论**：想「给行加 padding 让返回键远离边缘」，
必须**在按钮内部把等量位移补回来**，否则墨迹会被一起推右。
实测：`padding: 0 8px`（行）+ `justify-content: flex-start; padding-left: 4px`（按钮）
→ `8 + 4 = 12`，正好等于原来的 `0 + (44-20)/2 = 12` → 触摸区右移而**墨迹不动**。

**这段历史要留着，因为它记着一次「理由消失」**：那 4px 补偿原本服务两条理由 ——
① 与报表页当时那个 28px 左对齐大标题（文字左边缘 16px）**同轴**；
② 贴合参考图 `IMG_4201`（iPhone 16 Pro @3x）实测的箭头墨迹 **17.0pt**（= 17.94px）。
2026-09-17 大标题收进顶栏 → **理由 ① 当场消失**，只剩参考图一条撑着 ——
于是 luchao 决定**撤掉补偿，统一到 25.94**。
→ **教训不是「哪个数对」，而是「一个值靠两条理由撑着时，废掉一条必须立刻重新审」**：
否则它会以"历史遗留"的身份活很久，而且没人说得清该不该动。

**当前状态（脚本实测，5 页一致）**：

| 页面 | 触摸区左边缘 | 箭头**墨迹**左边缘 | 按钮内对齐 |
|---|---|---|---|

### 1.8 顶栏标题：绝对定位居中，**必须**配 `pointer-events: none`（2026-09-17 新增）

报表页标题从「返回行 + 左对齐 28px 大标题」收进那 44px 返回行（luchao 要求）：
标题 `$font-h2`(17/24) + 600、**居中**，吸顶区 **137px → 89px**（44 顶栏 + 45 Tab）。

⚠️ **别用 `.nav-title { flex: 1; text-align: center }`**（流水页 / 分类页的写法）：
那是在**剩余空间**里居中，不是**在屏幕里**居中。左侧 44px 返回键、右侧为空
→ 文字中心比屏幕中心**右偏 (44+8)/2 = 26px**。宽标题不明显，「报表」两个字一眼能看出。
正解是绝对定位（`left/right: 0` + `text-align: center`），这也是 iOS 的做法。

⚠️ **`pointer-events: none` 不是可选优化，是必需项**：绝对定位的标题横跨整行、
且晚于返回键绘制，漏掉它就**整块吃掉返回键的 44×44 触摸区** ——
页面照常渲染、标题照常显示，只有点下去没反应，**肉眼完全看不出来**。
同类漏法：忘了给 `.nav-inner` 加 `position: relative`，标题会相对更外层定位，换宽度就飘。

两条都已进守卫（`check-ios-tokens.mjs` §14，共 **112 项**断言；两条都做过负向验证 ——
删任一条 → 退出码 1 并打印出违规文件）。

**验收方式（可复现）**：`node scripts/verify-topbar.mjs`（**26 项**断言）。它用
`document.elementFromPoint()` 在返回键触摸区的**左上 / 中心 / 右下**三点做命中测试，
断言都落在返回键内 —— 只量几何是查不出「被盖住」的（`getBoundingClientRect` 完全正常）。

**负向验证过，且结果正是"三点都要量"的理由**：删掉 `pointer-events: none` 后，
只有**中间那一点**报 `MISS(uni-text)`，左上与右下两点仍然 `back` ——
**只量一个点就会漏掉这个 bug**。

## 五、验证方法论（跨端通用，2026-09-30 重建）

> ⚠️ **本文档原本要在 2026-09-26 的整理里落地这一节，但实际没写进来** ——
> `MEMORY.md` 却已经写着「见 §五 的 20 条」，于是引用悬空了一个月（是一处**假宣称**）。
> 2026-09-30 依 MEMORY 的摘要 + 各 `memo/*.md` 与脚本注释里的实证重建；
> **历史上被引用过的编号（13 / 17 / 20）保持不变**，其余编号为重建时的顺序。
> 找到新规律就往这里加，**不要再让 MEMORY 指一个不存在的章节**。

**总纲：判据比实现更容易出错。** 一个"永远绿的校验器"比没有校验器更危险 ——
它让你以为验过了。以下 20 条都是"判据本身失效"的实例。

1. **"控件是真的、效果是假的"也算假控件** —— 排序菜单点了有反馈、`self.order` 也赋值了，
   但它**从没进过请求参数**，列表纹丝不动。判据：**看实际请求参数，不是看有没有控件、有没有赋值。**
2. **否定性结论要先问「它凭什么能失败」** —— 写任何 check 之前先想：**什么情况下它会红？**
   想不出来，就说明它测不到东西（本项目反复出现，见第 20 条）。
3. **负向验证是硬要求**：没验过"能报错"的校验器等于没有校验器。
   改完关键逻辑，**手动把修复回退一次**，确认判据真的变红。做不到就别声称"已验证"。
4. **要用"只差一点点"的输入去测**，别用"错误输入"。例：校验"事件必须有前缀"，
   喂"随便一行日志"是没用的 —— 它会被"坏 JSON"分支兜住，照样全绿。
   要喂**垫够前缀长度的形似事件**才测得出来。
5. **布尔 / 枚举字段要把每种取值都钉住**。只断言"正常路径下为真"等于没测：
   把实现改成"恒真"照样全绿。
6. **不要先截断响应再 `JSON.parse`**。截断必然让解析失败，判据会静默退化成
   "永远的：非 JSON 响应"。**打印时截断，判据用未截断的全文。**
7. **"数出现次数"的判据，边界值要人工造样本核一遍** —— 零引用扫描用「≤2 次即死」，
   会把"1 次定义 + 1 次调用"的正常方法**误报成死代码**（第 20 条）。
8. **找"鉴权判据端点"时，先确认它真的需要登录**。用不需要凭证也能 `code=0` 的端点
   去测"cookie 有没有用"，等于用一个**永远不会红的校验器**。
9. **判据必须写成「code 对 **且** 数据真的回来了」**。只看 `code` 会漏掉
   "服务端不报错、但返回里根本没有 data"的情形。
10. **同一概念的所有出现位置全局搜一遍**；⚠️ **Bash `grep` 对中文会假阴性**，
    中文检索一律用 Grep 工具（这条本身也是"判据不可靠"的例子）。
11. **容器高度归零 ≠ 内容消失**（iOS 要补 `clipsToBounds`）；
    **两视图约束重叠 = 一个被盖住且不报错** —— 这类问题**必须看图**，读代码看不出来。
12. **交互态巡检必须带「守卫」**：点空 / 路由失效会**静默量到别的屏**，还给你一片绿。
    `reflow-audit` 的 `steps` + `guard` 就是干这个的。
13. **「点不开就扫不到」是通用盲区**：数字键盘、滚动轮、各类弹层都不在"页面加载完"的 DOM 里。
    能自动化的补进脚本，**补不进的写进「人工验收清单」**，别假装扫过了。
14. **居中必须用绝对定位**：`flex:1 + text-align:center` 是在"**剩余空间**"里居中，
    左侧有返回键、右侧为空时会**右偏 26px**。居中层还要 `pointer-events: none`
    （否则它盖住右侧按钮，图标在、点不动）。
15. **"`scrollWidth` 没超标"不能当验收依据**：`body` 有全局 `overflow-x: hidden`，
    横向滚动条永不出现；真实溢出表现为"被裁掉"或"压邻居"。
16. **改完必须回读 dev server 实际吐出的内容**：HMR 不一定跟上，
    改了磁盘但服务的是旧模块 → **负向验证会"第一次不生效"**。
17. **跑 iOS 测试前必须 `simctl uninstall` App**：测试 bundle 在 App 包的 `PlugIns/` 里，
    App 在运行时不换 → 跑的是**旧代码**，"全绿"毫无意义（已封进 `scripts/run-tests.sh`）。
18. **同一处的"两半"要一起测**："改成 null" 与 "改成另一个非空值"是同一个坑的两半 ——
    只测一半等于没测（2026-09-30 流水改分类就是这么漏的，见 §1.1）。
19. **判据要落在「最里层」**：例：测 picker 的层级必须断言 `.uni-picker-container`，
    只断言外层 `.uni-picker-custom` **会漏掉 bug**（外层已经 3000、里层还是 999）。
    同理，"数页面上有几个容器"这类断言要挑**可见的那一个**（隐藏实例会让它变成假失败）。
20. **零引用扫描的阈值要留人工复核**：`ABPlaceholderViewController` / `ABCache` 是真死代码（该删），
    但 `fromDictionary` 是扫描脚本**假阳性**（该留）。**脚本给候选，人来定生死。**
21. **测压缩 / 编码这类「传输层」行为，不能用会自动解压的客户端**（2026-10-01 实证）：
    Node 的 `fetch`（undici）会自动补上 `Accept-Encoding: gzip, deflate, br` 并**透明解压**响应体。
    于是「带不带 gzip 头」量到的字节数**完全一样**、也看不到 gzip 魔数，判据静默退化成
    「永远的：`Content-Encoding` 存在」——第一版脚本就此给出**假阳性**，还顺手把
    「不带该头应返回原文」误判成失败（因为请求压根没做到"不带"）。
    ✅ 正确做法：用 **`node:http` 读原始 socket 字节**，并额外校验两件事 ——
    **gzip 魔数 `1f 8b`**，以及返回的字节数**是否等于磁盘上 `.gz` 的字节数**
    （后者才能区分"走了预压缩"和"现场动态压"，两者长度通常不同）。

**三条元规律**（从上面提炼）：

- **"读不到" ≠ "不存在"**：读不到滚动量可能是找错容器（`uni-page-body` vs `document.scrollingElement`）；
  读不到请求参数可能是没接对钩子。**先怀疑测量方法，再怀疑被测对象。**
- **任何"影响服务端结论"的操作都要重新问一次**：换账本、改开关、改时间区间之后，
  旧的预览 / 汇总结果一律作废，必须重算。
- **注释写对了、实现却没用上，通常是因为两处代码离得太远**：
  当一个值同时被"展示"与"写入"两条链路消费时，**要共用同一个事实源**，而不是各写一份注释。

## 八、传输层：压缩与缓存分层（2026-10-01 新增）

> 起因：排查前端「丝滑度」时发现，**代码层面其实已经做过不少刻意优化**（骨架屏、
> color-icons 分包、scroll-view 显式高度、backdrop-filter 降级…），但**传输层完全是裸的**
> —— nginx 没开 gzip、没有任何缓存头、后端响应不压缩。实测单次冷启动要传 **5.3 MB**。
> 这一节记的是「**哪一层负责什么**」以及几个**会静默失效**的点。

### 8.1 三层分工（不要越界，否则互相抵消）

| 层 | 负责 | 不负责 |
|---|---|---|
| 应用层（`koa-compress`） | `/api` 的 JSON 响应 | 静态文件 |
| nginx（`gzip_static` + `gzip`） | 静态产出（JS/CSS/HTML/SVG） | `/api`（上游已压，nginx 不重复压） |
| 浏览器缓存 | 带 hash 的产物存一年、入口 HTML 每次验证 | —— |

- 后端中间件 `src/middleware/compress.middleware.ts`：`match()` 只认 `/api`，阈值 1KB，
  **只开 gzip**。不开 `br`/`zstd`：部署是明文 HTTP，浏览器只在 HTTPS 下才广告 `br`，开了就是死分支；
  也不单独开 `deflate`，因为 **nginx 的 gzip 模块同样只服务 gzip** —— 端到端保持一致，
  避免出现"接口压了、静态没压"这种同客户端两种待遇的怪现象。
- 注册位置在 `src/configuration.ts` 的 `useMiddleware([...])` **数组第 0 项**（最外层）：
  koa-compress 是在 `await next()` 之后才读 `ctx.body`，必须站在 `ResponseMiddleware` 外面，
  等它把返回值包成 `{code,data,message}` 之后，压到的才是最终 body。
- ⚠️ **`gzip_static` 与 `gzip` 必须同时开**：前者吐构建时预压好的 `.gz`（运行时零 CPU），
  后者兜住任何没预压过的文件。只开前者 → 漏压的文件完全不压；只开后者 → 每次冷请求都现场压同一批静态文件。

### 8.2 预压缩：`scripts/precompress.mjs`

- 由 `deploy/build-and-export.sh` 的 **3/7 步**调用，位置在**两个前端构建完之后、打镜像之前**。
  ⚠️ 早于构建 → 压到上一次的旧产物；晚于打镜像 → 根本进不去镜像。
- **只压文本白名单**（js / mjs / css / html / json / svg / txt / xml / map / webmanifest），
  **跳过 PNG / WebP / WOFF2 / ICO** —— 它们本身已是压缩格式，再 gzip 几乎不缩、纯浪费 CPU。
  `static/cat-icons/` 下的图标是典型：**两套都不压**（`.png` 是 160×160 插画压不动，
  `.webp` 本身已是压缩格式）。**图片太大不是靠压缩解决的** —— H5 端已改成加载 WebP
  （1.884 MB → 0.215 MB，省 88.6%，见 §8.4），这份脚本只管把能压的**文本**压掉。
- **增量**：`.gz` 比源文件新就跳过，重复部署几乎零成本。
- **保留原始文件**（`.gz` 是额外产物，不是替换品）：nginx 只在客户端声明 `Accept-Encoding: gzip`
  时才用 `.gz`，否则回落原文件。两个文件都必须存在。Dockerfile 是整目录 COPY，无需改动。
- 阈值 **1024 字节**必须与 nginx 的 `gzip_min_length` **两处一致**，
  否则会出现"明明预压了、静态路径却不生效"的错觉。

### 8.3 缓存分层（判据：**文件名带不带内容 hash**）

| 路径 | 策略 | 理由 |
|---|---|---|
| `/assets/`、admin 的 `/js/` `/css/` `/jse/` | 1 年 + `immutable` | 文件名带内容 hash，内容一变名字就变 |
| `/static/cat-icons/` | 1 年 + `immutable` | 文件名是拼音（**不带 hash**），靠 URL 上的 `?v=` 区分版本；H5 取 `.webp`、小程序/App 取 `.png`（同目录并存） |
| `/static/` 其余（logo / app-icon / tabbar 图标） | **7 天** | 固定名、**没有版本号**；给一年会变成"我明明换了图，怎么还是旧的" |
| `index.html`、admin 的 `_app.config.js` | `no-cache` | 见 §8.5 |
| 所有 PNG / WebP | 不 gzip | 见 §8.2 |

⚠️ 用 `add_header Cache-Control` 时**不要加 `always`**：`always` 会把 404 也带上一年缓存
（浏览器于是把 404 记一年）。也不要 `expires` 与 `add_header Cache-Control` 同时写，会发出两个
`Cache-Control` 头。

### 8.4 图标的双份产物、平台切换与版本号（**H5 用 WebP，其余端用 PNG**）

**双份产物**：`static/cat-icons/` 下每个分类现在有**两个**文件 ——
`<拼音>.png`（小程序 / App 用）与 `<拼音>.webp`（H5 用）。都由
`scripts/gen-cat-icons.mjs` 一次生成（sharp，q90，effort 6），
实测 **1.884 MB → 0.215 MB（省 88.6%）**，平均像素误差 1/255 量级（合成白底后），肉眼不可辨。

- ⚠️ **为什么只在 H5 用 WebP**：小程序 `<image>` 加载**包内本地文件**走各端原生实现，
  不是浏览器内核 —— 无法离线确认它对 webp 的支持，一旦不支持就是**安静地显示空白**。
  小程序/App 的图标随代码包一起发版、本来也没有长缓存问题，用 PNG 零风险。
- ⚠️ 两套必须**按基名一一对应**。映射表 `CAT_ICON_FILES` 的值是**不带扩展名的基名**
  （`"wucan"`，不是 `"wucan.png"`），扩展名由 `utils/catIcon.ts` 按平台拼。
  **改了映射格式却没改消费方（或反之）会拼出双扩展名**（`.png.webp`），
  两端同时坏 —— 这是本次迁移唯一的高危耦合点。

**产物裁剪（构建期按平台剔除"本端不用"的那一套）**：uni-app 把 `src/static/` **原样**拷进
每个端的产物、**不按端裁剪**（见 `@dcloudio/vite-plugin-uni/dist/plugins/copy.js`）。
于是 H5 产物里会躺着一整套永不请求的 PNG，小程序包里会多出一整套用不到的 WebP。
`vite.config.ts` 的 `pruneUnusedIconFormat()` 插件在构建结束时删掉本端用不到的那一侧，实测：

| 端 | 删除 | 省下 | 该端实际需要的 |
|---|---|---|---|
| H5 (`dist/build/h5`) | 94 个 `.png` | **1.88 MB** | 94 个 `.webp`（0.21 MB） |
| mp-weixin | 94 个 `.webp` | 0.21 MB | 94 个 `.png`（1.88 MB） |

- ⚠️ 挂在 **`closeBundle`**、不能挂 `writeBundle`：`static` 的拷贝发生在 `uni:copy` 的
  `writeBundle`（而且它会 await 文件监听器），写进 `writeBundle` 就是**和自己的拷贝赛跑**。
  插件在 `plugins` 数组里必须排在 `uni()` **之后**。
- ⚠️ **只动产物、绝不动源目录**：`src/static/cat-icons/` 永远保持两套齐全 ——
  同一个源目录要供**所有**端的构建使用，删源文件等于毁掉另一端的构建。
- ⚠️ **安全阀**：只删「**同名另一套确实存在**」的文件。若某张图只有被删的那一侧，
  **保留并告警**（已实测：埋一个孤儿 `.png` 进去，它被保留而不是删掉）。
  宁可留一个多余文件，也不能让图标凭空消失（`<image>` 会安静地显示空白）。
- ⚠️ 平台表是 `vite.config.ts` 的 `ICON_FORMATS`，**必须与 `utils/catIcon.ts` 的条件编译一致**：
  前者决定"产物里留哪套"，后者决定"运行时请求哪套"。不一致 = "端上要 `.png`、产物里只有 `.webp`"
  → 图标整片空白。**改平台策略要两处一起改。**
- 为什么不能用 uni 自带的 `static/<platform>/` 机制代替：copy.js 只认**平台名**目录
  （`static/h5/`、`static/mp-weixin/`…），而我们要按**格式**切分，且"除 H5 之外的全部"
  这一侧没法用一个平台名表达。

**版本号 `?v=`**：
- `vite.config.ts` 的 `catIconVersion()` 算 `src/static/cat-icons/` 的**目录内容 hash**
  （文件名 + 内容，8 位 hex；覆盖 `PNG + WebP` **全部** 188 个文件），
  经 `define` 注入 `__CAT_ICON_VERSION__`，H5 的 URL 带上它。
- 为什么用**目录内容 hash** 而不是构建时间戳：图标没变 → 版本号不变 → 回访用户直接命中缓存；
  用时间戳则每次部署都让所有人重下图标。
- ⚠️ **小程序 / App 端绝对不能带 query**：这些端把 `/static/xxx.png` 当作**包内本地文件路径**解析，
  带 query 很可能直接加载失败（`<image>` 安静地显示空白，很难查）。
- ⚠️ 写法必须是「`let src` + 条件编译赋值」，**不能**把两段 `return` 各包一层 `#ifdef`：
  `vue-tsc` 检查的是**未经 uni 预处理**的源码，两个 `return` 它都看得见 → 报不可达代码。
- ⚠️ **两段条件编译必须互补且互斥**（`#ifdef H5` + `#ifndef H5`），才能保证
  **每个平台都必定给 `src` 赋了值**。**别改成平台白名单**（如 `#ifdef MP-WEIXIN`）——
  那样 App / 支付宝端会落进初始空串 → URL 为空 → 图标整片空白且不报错。
- ⚠️ 算 hash 时**跳过隐藏文件**（macOS 的 `.DS_Store` 会随 Finder 浏览变化，参与进去会破坏
  跨机器可复现性），排序**不能用 `localeCompare`**（受系统 locale 影响）。
- 改图标后 **dev server 要重启**才会更新版本号（dev 下静态资源本来不长缓存，影响可忽略）。

**校验**：`node scripts/verify-cat-icon-assets.mjs` —— 只读磁盘、秒级，30 条判据覆盖
"两套是否按基名一一对应、映射格式、文件头/尺寸/alpha、WebP 是否真的更小（含**反向**检查：
有没有哪个 webp 反而更大）、以及**用 uni 真实预处理器验两端产出的 URL**"。
它是 `scripts/verify-cat-icons.mjs`（Playwright，需起 dev server + Chromium）的**离线前哨**：
改图标后先跑它，再去跑那个重的。

### 8.5 三个会静默失效的点

1. **绝不要给 nginx 的 `/api` 加 `proxy_set_header Accept-Encoding "";`** ——
   它会抹掉客户端的编码偏好，后端于是不再压缩；而 nginx 的 `gzip_proxied any` 只压"未压缩的"
   代理响应 → 接口体积悄悄回到未压缩状态，**不报任何错**。已在 `deploy/nginx.conf` 的
   `location /api/` 就地写了警告注释。
2. **`index.html` 必须 `no-cache`** —— 它里面写着当次构建的 hash 文件名，也是 `?v=` 新地址的唯一入口。
   把它缓存住 = 把用户锁死在旧版本上（`?v=` 再新也传不到用户）。
   `no-cache` 不是"不缓存"，而是"每次回来验证"，命中 ETag 只回 304，几乎无开销。
3. **`dist/` 陈旧 = 部署旧代码**（本次实际踩到）：源码改到 10-01，而 `frontend/dist` 停在 09-30，
   旧产物里的图标是 **4.8 MB**（新版 2.1 MB）—— 等于白白多传 2.7 MB **外加**跑着旧逻辑。
   部署一律走 `deploy/build-and-export.sh`（它每次都会重新 build 前后端），不要手工拼镜像。
   后端同理：`npm start` 走 `dist/`，改完 `src/` **必须 `npm run build`** 才生效。

### 8.6 实测数字（2026-10-01）

| 项 | 前 | 后 |
|---|---|---|
| App 前端 JS+CSS | 2254.8 KB | **735.9 KB**（-67%） |
| 中台 admin JS+CSS | 3021.0 KB | **897.7 KB**（-70%） |
| 分类图标目录（含陈旧产物修复） | 4.8 MB | **2.1 MB** |
| 其中：H5 实际下载的图标（WebP） | 1.884 MB（PNG） | **0.215 MB**（-88.6%） |
| `/api` 大 JSON | 未压缩 | gzip 生效 |

**验收判据**（两条缺一不可，理由见 §五 第 21 条）：
临时 `nginx:alpine` 容器挂载产物，用 `curl` 看头；关键是
**nginx 返回的字节数 == 磁盘上 `.gz` 的字节数** —— 只有这条相等才能证明走的是
`gzip_static` 预压缩，而不是"看起来也压了"的动态压缩。
另需单独验一次**动态兜底**路径：造一个没有 `.gz` 的文件，确认它仍被现场压缩。

⚠️ **"产物变大 / 用户下载变小"曾经是两回事，现在只剩后半句**：双份产物刚落地的**短窗口**里，
`frontend/dist` 比原来**略大**（多了 0.215 MB 的 WebP）。随后补上了构建期裁剪
（`pruneUnusedIconFormat()`，见 §8.4）—— 现在 H5 产物里**只有 WebP**，
同一次干净构建下不裁剪会是 4.50 MB，裁剪后 **2.61 MB**。
判据始终是"用户 downloads"，不是"镜像体积"；但**别再拿"dist 变大"当预期现象**。
