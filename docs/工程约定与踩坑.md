## 一、实现约定

### 1.1 数据与接口（只记会静默出错的）

- **金额全程字符串**（`"12.34"`）；**ID 是 BIGINT → 字符串**（别用 `===` 比数字）。
- **改外键字段时，实体上已加载的关系对象要一起改**，否则 TypeORM 会回填旧值（踩过 3 次）。
- **TypeORM raw query 不支持 `:name` 命名参数**，必须 `?` + 数组。
- **SQL 别名别用保留字**（`key` 在 MariaDB 直接语法错误 → 500），用 `groupKey`。
- **路由顺序**：`GET /transactions/summary` 必须在 `GET /transactions/:id` **之前**注册。
- **列表与汇总共用同一套筛选**（后端模块级 `applyFilters()`）。分类多选传**一级会连带命中其下二级**。
- `src/` 下的脚本**不要无条件自执行**（Midway 扫描器会加载它，会把服务带走）。
- 本地调试 curl 必须 `--noproxy '*'`，否则被 127.0.0.1:7897 代理拦成 502。
- ⚠️ **luch-request 的签名是 `delete(url, data, options)` —— 第二个参数是「请求体」，不是 axios 那种 config。**
  `http.delete(url, { params: {...} })` 里的 `params` 会被当成 **body** 发走（还是 JSON 体），
  URL 上根本没有查询串 → 后端读 query 的 DTO 报 `"xxx" 是必须的`（422 / 40000）。
  **查询串一律自己拼进 URL**：``http.delete(`/accounts/${id}?confirmName=${encodeURIComponent(name)}`)``。
  （2026-09-17 用户报「删除账本，名字输对了却提示没拿到名称」，根因就是这个。
  自仓库初始化起就存在，一直没被发现是因为它**表现成后端校验失败**，看着像后端的问题。）
  同类但**合法**的写法：`http.get(url, { params })` —— 那里 `{ params }` 落在 options 位置，别一起"修"错。
- ⚠️ **列表接口的 `size` 上限是 100**（`src/transaction/dto/transaction.dto.ts` 的
  `RuleType.number().integer().min(1).max(100)`）。**传超限值是被整条拒绝，不是截断** ——
  后端返回「输入有误，请检查后重试」，而调用方的 failure 分支通常只打一条日志，
  **界面上完全看不出来**（表现成"这个页面就是没数据"）。
  需要全量必须**循环分页**：前端走 `pages/export` 的 `PAGE_SIZE=100` / `MAX_PAGES=200`，
  iOS 走 `ABTransactionService.getAllTransactions:`。
  **凡「有上下限的数值参数」都要对着后端 DTO 核一遍，别"填个够大的数"。**
  （2026-09-25 iOS 移植时发现三处踩到：流水明细 / 日历 / 导出分别填了 500 / 500 / 10000，
  三个页面全都没数据，一直没人发现 —— 因为失败是**静默的**。查法：
  `xcrun simctl spawn booted log show --last 8m --predicate 'process == "MyAccountBook"' | grep -F "[flow]"`。）

### 1.2 颜色与字体（改界面前必读）

- **v1.1 有效值**：分隔线 `#F1F1F1` · 页面底 `#F8F8F8` · 卡片**零描边** + 圆角 16 ·
  文字 `#222226` / `#6B6B72` / `#9A9AA0`（仅装饰）· 主色金 **`#A85F12`**（图形金 `#E4AD77` 配白字仅 1.99）·
  青绿 `#56C4C5` 图形 / `#2E9496` 大字 / `#0E7375` 小字。
- **语义色**：收入 `#D92D20`（红）、支出 **`#0F7B7C`（青绿）** —— 2026-09-16 v1.1 定案（原 `#0B8038`）。
  `$success`/`$danger` **不动**（语义不同）。投资模块若新增须另建 `market-up`/`market-down`。
- **改任何颜色都要重算对比度。背景一变，前景必须重算** —— 本项目已发作**四次**。
- **文字禁用 `opacity`**（白字 4.52 × 0.85 只剩 3.69）。要"次要"就换 token。
- **最小字号 12px**；字重只用 400/500/600（**禁 700**，CJK 伪粗体）。
- 金额一律 `font-variant-numeric: tabular-nums` + 右对齐 + 带正负号（色不单独承担语义）。
- **uni-ui 的 `$uni-*` 在自己块内重声明且不带 `!default`**，会覆盖本项目赋值
  （唯一生效的是带 `!default` 的 `uni-easyinput.$uni-border-1`）。库限制，别再"修"。
- 批量改色用「行号 + 整行内容」双断言的脚本，**别只靠 grep 定位**（无 `#hex` 的样式行 grep 不到）。
- ⚠️ **调色板缺口（无解）**：没有「能压白卡被看见 **且** 金字保持 4.5:1」的浅金表面
  （`$v11-gold-soft` 压白卡仅 1.07）→ **浅金底只能作氛围，必须再给一条金色细边**才成为「可点表面」
  （分类选中 / 日期「今天」/ 回收站「恢复」）。**删掉那些边 = 选中态直接消失。**

### 1.3 重排（320px / 200% 字号）

- **`flex: 1` 等价 `flex: 1 1 0%`**。带 `flex-wrap` 的行里是陷阱：basis 为 0 意味着"它认为这栏不需要空间"
  → 该换行的不换。**要留空间写 `flex: 1 1 auto`。**
- **flex 项默认 `min-width: auto`**，是顶破容器最常见原因 → 显式 `min-width: 0`。
- **固定宽度一律改 `min-width`**（`width:56px` / `width:18px` 这类都在大字号下卡出盒子）。
- **`flex-wrap: wrap` 在"本来放得下"时是 no-op**，是安全兜底。反之写 `min-width: 5em` 这类阈值
  **必须先用容器真实内宽核过**（我算成 288px，实际只有 260px）。

### 1.4 溢出的真实形态（验收方法）

本项目"溢出"**不表现为滚动条**：uni-app 给 `body` 加了全局 `overflow-x: hidden`，横向滚动条**永不出现**。
两种真实形态：①被祖先 `overflow:hidden` **裁掉**；②宽于自身盒子但与邻居**重叠压字**。
**这两种 `document.scrollWidth` 都测不到** —— "scrollWidth 没超标"绝不能作为验收依据。
`reflow-audit` 已知盲区：测不到**文字压在同一盒子内的装饰图形上**（环形图中心注解的约束是内孔 132px，
而非容器 180px）。**"没报"不等于"没问题"。** 它**不模拟 safe-area**，那类 bug 靠 `verify-safe-area.mjs` 抓。

### 1.5 uni-app 平台的静默陷阱

- **SVG 里不能写 `<text>`**：被编译成 `<uni-text>`，SVG 不认识 → **文字完全不渲染且不报错**。
  正解是文字走 **HTML 覆盖层**。**build / vue-tsc 全绿对这类静默空白毫无作用。**
- **`<text>` 被渲成 inline `<span>`，`text-overflow: ellipsis` 不生效** → 加 `overflow:hidden` 的结果是
  **被静默裁掉**。正解：让内容足够短（`shortMoney` 分档）。
- **`box-sizing: border-box` + 固定 `height` + `padding-bottom: env(safe-area-inset-bottom)` 会把内容挤扁**
  （实测 `.tab-item` 从 55 塌到 21）。**正解：height 也跟着安全区长**，并**先写不带 env 的 height 作兜底**。
- **`scroll-view` 不吃 flex 推导**（`flex:1+min-height:0` / `flex:1+height:0` 都失败），**必须给确定高度**。
- **`scroll-view` 的 `scrollTop` 是受控值**（脚本里赋值会被回写重置）→ 测滚动必须用**真实滚轮手势**。
- **`box-sizing` / `z-index` 类改动要同时看"被盖住的元素是否仍拦截点击"**。
- ⚠️ 用 `write` 工具写验证脚本会把 `\d` 转义成 `d`（正则失效致假失败），**用 heredoc 写**。
- ⚠️ `scripts/**/*.mjs` 是**双执行上下文**（主体跑 Node，`page.evaluate()` 回调跑浏览器）。
  `eslint.config.mjs` 里的 `document`/`window`/`location`/`history`/`localStorage`/`getComputedStyle`/`getCurrentPages`
  这 8 个全局缺一个就整片 `no-undef`。

### 1.6 只记「会静默出错」的页面约定

- **流水页**：⚠️ 切分组维度要**同时改 `unit` 和 `groupBy`**。弹层**贴屏幕底边升起、不留底栏高度**（有意）。
  `.nav` 吸顶：**渐变头高度必须实测**（写过 180 而实测 146 → 白图标压白页面）；搜索框展开会改变头高，**要重测**。
- **流水全屏搜索**：金额搜索 SQL 必须 `CAST(t.amount AS CHAR) LIKE :kw`（`t.amount LIKE` 匹配不到小数）。
  验证"搜索页内无分组"要限定在 `.search-page` 内（主列表 `.group` 仍在 DOM 里）。
- **`utils/period.ts`** 的「分组键 ↔ 日期区间」**必须与后端 `GROUP_FORMAT` 完全一致**（week 是 **ISO 周**）。
- **记一笔默认时刻**：**提交时**取 `new Date()`。⚠️ 必须单独存 `userClearedTime`
  （"没选过"与"主动关掉开关"都是 `null`，靠值分不开）。
- **主容器底栏 3 格**：⚠️ **凸起项居中取决于"它排第几"**（3 格时槽中心 16.7% / **50%** / 83.3%）。
- **`reflow-audit.mjs` / `diagnose-scroll.mjs` 的页面清单必须随结构变化同步**：失效的 `?tab=xxx`
  **不报错、会静默落到首页**（量的是首页却记为那个视图 = 假全绿）。

### 1.7 自绘顶栏的横向几何（2026-09-17 新增）

**约定**：自绘顶栏的返回行统一 `.nav-inner { padding: 0 $space-2 }`（**8px**）。
现有 5 个自绘顶栏页：流水 / 日历 / 回收站 / 数据导出 / **报表**。
（报表页原先漏了这层 padding，触摸区顶到视口左边缘 `x=0`，2026-09-17 已修。）

⚠️ **陷阱：`svg` 包围盒左边缘 ≠ 箭头的可见墨迹左边缘。**
`icon-chevron-left` 在 24 视口里只占中段，缩到 20px 后墨迹还要再内缩 **5.94px**
（≈ `size × 0.297`）。所以：

```
墨迹位置 = 触摸区起点 + 图标在按钮内的偏移 + 内缩（20px 图标 ≈ 5.94px）
```

**这条推出一个反直觉的结论**：想「给行加 padding 让返回键远离边缘」，
必须**在按钮内部把等量位移补回来**，否则墨迹会被一起推右。
实测：`padding: 0 8px`（行）+ `justify-content: flex-start; padding-left: 4px`（按钮）
→ `8 + 4 = 12`，正好等于原来的 `0 + (44-20)/2 = 12` → 触摸区右移而**墨迹不动**。

**这段历史要留着，因为它记着一次「理由消失」**：那 4px 补偿原本服务两条理由 ——
① 与报表页当时那个 28px 左对齐大标题（文字左边缘 16px）**同轴**；
② 贴合参考图 `IMG_4201`（iPhone 16 Pro @3x）实测的箭头墨迹 **17.0pt**（= 17.94px）。
2026-09-17 大标题收进顶栏 → **理由 ① 当场消失**，只剩参考图一条撑着 ——
于是 luchao 决定**撤掉补偿，统一到 25.94**。
→ **教训不是「哪个数对」，而是「一个值靠两条理由撑着时，废掉一条必须立刻重新审」**：
否则它会以"历史遗留"的身份活很久，而且没人说得清该不该动。

**当前状态（脚本实测，5 页一致）**：

| 页面 | 触摸区左边缘 | 箭头**墨迹**左边缘 | 按钮内对齐 |
|---|---|---|---|
| 流水 / 日历 / 回收站 / 数据导出 / **报表** | 8 | **25.94** | `justify-content: center` |

`25.94 = 8`（行内边距）`+ 12`（图标在 44px 按钮内居中）`+ 5.94`（墨迹内缩）。

**验收方式（可复现）**：`node scripts/verify-topbar.mjs`（**26 项**断言，含负向验证）。
它用 `getBBox()` 量墨迹，而不是 `getBoundingClientRect()` 量包围盒 ——
后者会给出"差 4px"的假信号，据此去改会把本来对齐的东西推歪。

### 1.8 顶栏标题：绝对定位居中，**必须**配 `pointer-events: none`（2026-09-17 新增）

报表页标题从「返回行 + 左对齐 28px 大标题」收进那 44px 返回行（luchao 要求）：
标题 `$font-h2`(17/24) + 600、**居中**，吸顶区 **137px → 89px**（44 顶栏 + 45 Tab）。

⚠️ **别用 `.nav-title { flex: 1; text-align: center }`**（流水页 / 分类页的写法）：
那是在**剩余空间**里居中，不是**在屏幕里**居中。左侧 44px 返回键、右侧为空
→ 文字中心比屏幕中心**右偏 (44+8)/2 = 26px**。宽标题不明显，「报表」两个字一眼能看出。
正解是绝对定位（`left/right: 0` + `text-align: center`），这也是 iOS 的做法。

⚠️ **`pointer-events: none` 不是可选优化，是必需项**：绝对定位的标题横跨整行、
且晚于返回键绘制，漏掉它就**整块吃掉返回键的 44×44 触摸区** ——
页面照常渲染、标题照常显示，只有点下去没反应，**肉眼完全看不出来**。
同类漏法：忘了给 `.nav-inner` 加 `position: relative`，标题会相对更外层定位，换宽度就飘。

两条都已进守卫（`check-ios-tokens.mjs` §14，共 **112 项**断言；两条都做过负向验证 ——
删任一条 → 退出码 1 并打印出违规文件）。

**验收方式（可复现）**：`node scripts/verify-topbar.mjs`（**26 项**断言）。它用
`document.elementFromPoint()` 在返回键触摸区的**左上 / 中心 / 右下**三点做命中测试，
断言都落在返回键内 —— 只量几何是查不出「被盖住」的（`getBoundingClientRect` 完全正常）。

**负向验证过，且结果正是"三点都要量"的理由**：删掉 `pointer-events: none` 后，
只有**中间那一点**报 `MISS(uni-text)`，左上与右下两点仍然 `back` ——
**只量一个点就会漏掉这个 bug**。

## 二、账本级分类（2026-09-16 起，重大变更）

分类从「用户级共享」改为「**账本级隔离**」，详见 `docs/账本级分类设计文档.md`。
`categories.account_id`（NOT NULL，FK CASCADE），唯一键 `(account_id, name)`。

- **默认账本 = 母本**：新建账本的候选分类来自它；**它的分类不允许删除**（40006）；
  删默认账本时新默认账本会从 preset 重建全套 89 个。
- **两道保护**：分类下**有交易**（未软删）禁删 → 40004；默认账本分类禁删 → 40006。
- **核心不变量**：交易的 category_id 所指分类，必须与交易同 account_id。
- **合并账本**：分类**按 name 匹配**；去重指纹用**分类名**而非 id。
- **前端**：`categoryStore` 绑定当前账本（切账本自动重载）；新增页 `account-new`/`account-category`/`account-import`。
- **`copyAll`**：`POST /accounts` 默认 true；false 时按 `categoryIds`（**空数组 = 一个都不要**，与不传不同）。
- **踩过的坑**（都已修 + 有回归）：软删除交易未过滤 / 空数组被当「全选」/ DTO 加了 `.required()` 拦掉空数组。

## 五、验证方法论：二十条会反复咬人的规律

> 这些是**跨页面、跨端（前端 / iOS）通用**的教训 —— 动验证脚本或做验收前先读一遍。

1. **同一概念的所有出现位置必须全局搜一遍。** ⚠️ Bash 的 `grep` 对中文会假阴性、裸搜 `frontend/` 会超时
   → **中文检索用 Grep 工具；搜 `.workbuddy/`（被 gitignore 跳过）用 Python 遍历。**
2. **同一文件的多处修改必须串行**：并行发两个 `Edit` 会**静默丢改动**（都报 success）。改完回读确认。
3. **新写的校验断言必须做负向验证**：故意改错 → 确认报错且退出码非 0 → 改回。
   **没验过"能报错"的校验器等于没有校验器。**
4. **判据本身也要验收**：`reflow-audit` 第一版 `bad` 判据漏了「被祖先裁掉」一桶，于是"被裁 1 处"仍显示 ✅。
   **"报告里写了问题却判定通过"的脚本比没有脚本更糟。**
5. **会改 DOM 的测量脚本，读和写必须分两趟**（边遍历边写内联 `font-size` 会逐层复利，实测 60→120→240px）。
6. **验证脚本必须自建前置条件**：同一 URL 连续巡检时 **hash 变更不重新挂载组件**（`?tab=xxx` 全无效）
   → **跑前复位状态；跨页巡检每次显式 `page.reload()`。**
7. **接手别人做了一半的改造：核实进度只看代码，不看文档。** 两次实例：提交信息写「阶段 2 三张样板屏」
   实测只做 3/5；iOS 文档宣称「拖拽排序完成」实测只有服务层接口、UI 是假控件。
   判据：`git grep -l 'v11' src/` / `grep -rn "<方法名>" --include="*.m" --include="*.h" .`（只匹配到
   `.h` 声明 + `.m` 定义两行 = 零引用）。
8. **批量改名 token 必踩的两个坑**：
   - **只换背景没换前景 → 白字压浅底 = 消失。** 流水页渐变头改浅金后 nav 图标/标题仍是 `$text-inverse`，
     压 `#FDF6EF` 只有 **1.07:1**。不报错、脚本也抓不到，**只有看图才发现**。
   - **FL-1 里页面底与卡片同白（一个 token 两用）**，改名成 v1.1 灰底后「白载体」会跟着变灰。
     判据：**它是页面本身，还是浮在页面上的一块？** 后者一律 `$v11-bg-card`。
     ⚠️ **映射表按字面值定，不按名字** —— `$bg-page` 听着像页面底，字面值却是 `#FFFFFF`。
9. **uni-app 的 `scroll-view` 上加左右 `margin` 会让整页横向溢出**（不吃 flex 推导、宽度按视口算）。
   列表要么「白色通栏」，要么在 scroll-view **内部**套卡片容器。实测 320px 视口下文档宽变成 336。
10. **中文禁则能让一整句「不可断」，于是"溢出不足一个字"时浏览器选择不换行、直接吃掉右边距。**
    实测：`一级分类（顶层分组）` 在 320px + 200% 字号下，内容 300px 挤进 288px 的盒子 ——
    `word-break: break-all` 与 `overflow-wrap: anywhere` **都无效**（不能在「（」前断行）。
    → **修法不是调 `word-break`，而是拆句**：值 + 说明分成两个元素 + 容器 `flex-wrap: wrap` 兜底。
11. **校验脚本自己也会过期，而且过期方式是"静默失效"。** 实例：`verify-color-icon` 用的 `.group-header`
    早已改名成 `.row.root-row` → 脚本超时失败 → **没人再跑它**；`verify-icon-picker` 的清理逻辑调
    `/api/categories` **漏传 `accountId`** → 返回 40000 → 报"没找到刚创建的分类"（**误导性极强**）。
    → **改接口签名 / 改类名时，必须把 `scripts/verify-*.mjs` 一起搜一遍。** 清理逻辑要**大声报出真实
    HTTP 错误**，别用"没找到"把失败盖住。
12. **断言自己也会骗人，三种方式**：
    - **正则缺词边界 → 假通过**：断言「焦点环基于 `$v11-gold`」写成 `/\$v11-gold/` 会匹配到
      `$v11-gold-fill`。**凡断言"等于某变量"必须补 `(?![\w-])`。**
    - **计数类断言变了，先查原因再改数字**（`record` 删的是死样式 `.picker`，−1 合理；`category-new`
      拆句新增元素，+1 合理）。**没查清就改数字 = 把信号抹掉。**
    - **`build:h5` 报 `Build failed with errors` 不一定是代码错**：日志里有
      `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]` 是沙箱拦了构建自己的清理动作。
      **做法：先分批清空 `dist/build/h5/assets/` 再重编。** SCSS 未定义变量才是真错误（带 `Undefined variable`）。
13. **绝对定位的覆盖层会吃掉它下面的触摸区，而且完全看不出来。** 把 `.nav-title` 全宽绝对定位居中后，
    它**同时盖住了返回键的 44×44** —— 页面照常渲染、`getBoundingClientRect` 一切正常，**只有点下去没反应**。
    → 覆盖层一律配 `pointer-events: none`；父级要 `position: relative`。
    → **验收要量"能不能点到"，不是量"在哪"**：`document.elementFromPoint()` 在触摸区左上/中心/右下三点做
    命中测试。几何探针永远查不出这一层。已进守卫 `check-ios-tokens.mjs` §14。
14. **控件是真的，但效果是假的 —— 也要按"假控件"处理。**（2026-09-25 iOS 实测新增）
    「排序」菜单存在、点了有反馈、`self.order` 也确实被赋值 —— 但它**从没进过请求参数**，
    所以点完列表纹丝不动。同类还有「筛选」只有 6 个预设项、真面板没做。
    判据：**控件不能只看"有没有"，要看"输入最终有没有到达后端"** —— 断点/日志打出实际请求参数比对。
15. **容器高度归零 ≠ 内容消失。** 把一条提示条的高度约束改成 0 后，里面的 label 仍在原位置绘制
    （只是被容器裁不裁的问题），表现为**顶栏下面露一条半截文字的残影**。Android/iOS 都会。
    修法：容器补 `clipsToBounds = YES`（iOS）/ `overflow: hidden`（CSS）。**这类问题编译器、约束诊断都不报。**
16. **两个视图约束重叠 = 一个被另一个盖住，而且完全不报错。** 分类多选的折叠箭头与分类图标都放在
    `left: 8` 附近 → 图标后加、盖住箭头 → **箭头"根本看不见"**，但约束、渲染、点击全无异常。
    修法：给前一个元素**让位**（右移到不重叠处）。**判断方法是看图，不是看约束诊断。**
17. **`xcodebuild test` 可能跑在模拟器上"旧的已安装 App"上。**（2026-09-25 iOS 实测）
    测试 bundle 就在 App 包的 `PlugIns/` 里，App **已在运行**时 `xcodebuild test`
    不会把它换成新的 → 跑的是**旧代码 / 旧测试**。
    实测踩到：故意把一条断言写反，仍然报「✅ 全部通过」；`simctl uninstall` 后重跑才如期变红。
    ⚠️ **这个坑没有任何报错、也不改变输出格式** —— 比"测试失败"危险得多。
    → **跑测试前先 `simctl terminate` + `simctl uninstall`**（已写进 `scripts/run-tests.sh`）。
    **推广：凡"跑在某个已安装产物上的测试"，都要先确认产物是新的。**
18. **`@[@"a", @"b"]` 不能直接写在 `XCTAssert*` 之类宏的参数里。**（2026-09-25 iOS 实测）
    这个 @[@"a", @"b"] 里的逗号**会被预处理器当成宏参数分隔符**（只有圆括号能保护逗号，
    方括号和花括号都不行）→ 报 `expected identifier or '('` / `too many arguments`，
    而且报错行号指在奇怪的位置，很难看出是宏展开问题。
    修法：给字面量套一层圆括号 `XCTAssertEqualObjects(x, (@[@"a", @"b"]))`，
    或改成传逗号分隔字符串（本项目的测试用 `sel:@"a,b"` 这种写法绕开）。
19. **给 `NSUInteger` 夹上下限时，别直接 `MIN(size.unsignedIntegerValue, max)`。**
    负数的补码是巨大正数 → `MIN` 判它"没超" → 再被 `MAX` 抬成**上限**
    （`-5` 变成 `100` 而不是 `1`）。**单测抓到过一次。**
    正确写法：先用 `NSInteger` 判符号，再决定夹哪一边。同理适用任何"从 NSNumber 取值再夹"的地方。
20. **"按出现次数判死代码"的启发式，边界值必须人工核一遍。**（2026-09-26 iOS 实测）
    零引用扫描脚本的判据是「全文出现 ≤ 2 次即死」，而一个**正常的、刚好只被用一次**的方法
    恰好是「1 次定义 + 1 次调用 = 2」→ 被误报成死代码。
    实例：`fromDictionary` 真实被 `ABOfflineQueue.m:95` 调用；同批误报的还有
    `ABQueryBuilder` 的三个白名单辅助方法。**阈值应是 ≤ 1。**
    修正后重跑：服务层 47 个方法判死 0 个（旧阈值误报 4 个）。
    **推广：任何"数出现次数"的判据（零引用 / 覆盖率 / 重复代码），
    都要先把边界值（0/1/2）手动造一遍样本，确认它不误伤。**
