## 调研：uni-app 页面转场动画方向能否自定义（结论：仅 App 可行）
- 官方口径（api/router#animation）：「本 API 仅 App 支持，小程序自身不支持自定义动画，H5 走单页动画方案」。
  默认：非纯 nvue 项目 App 端 = 进入 `slide-in-right` + 返回 `pop-out`；纯 nvue(render native) = `pop-in`/`pop-out`，且 **pages.json/navigator 配动画无效，只能 API**。
- H5 实测：读 `node_modules/@dcloudio/uni-h5/dist/uni-h5.es.js`，`ANIMATION_IN` 数组只用于 props validator，包内无任何消费它的 transform/transition；
  `style/framework/base.css` 里 `uni-page/uni-page-wrapper/uni-page-body` 只有定位样式 → **H5 端传 animationType 不报错也不动，页面切换本就无转场动画**。
- ⚠️ 关键坑：`pages.json`（globalStyle.animationType 或 style.app-plus.animationType，平台=App）**只能配「显示动画」**，关闭动画按内置配对表反推
  （slide-in-right↔slide-out-right、slide-in-left↔slide-out-left…）。想要「左进右出」必须额外在 `navigateBack({animationType:'slide-out-right'})` 显式指定；
  优先级 API = 组件 > pages.json。`.nvue` 页在 app-plus 下只认 titleNView/pullToRefresh/scrollIndicator。
- 其他：iOS 侧滑 `popGesture`(默认 close)/`disableSwipeBack` 会与新方向打架；Android 物理返回与小程序左上角返回走默认动画，需在 `onBackPress` 拦截兜底；
  navigationStyle:custom 的前端导航栏在转场期间会白屏（官方警告），本项目 7 个页面是 custom，改反向转场会被放大。
- 给出的落地建议：App 端低成本（pages.json + 封装 router.push/back + 关侧滑 + onBackPress）；H5 端需自绘（先验证 uni-page DOM 是否双节点共存）；小程序端不建议做（Skyline 自定义路由风险高 / page-container 只能弹层）。
