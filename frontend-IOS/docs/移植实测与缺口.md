### 编译

```bash
export PATH="/usr/local/bin:$PATH"
cd frontend-IOS
xcodebuild -workspace MyAccountBook.xcworkspace -scheme MyAccountBook \
  -configuration Debug -destination 'platform=iOS Simulator,name=iPhone 17' \
  -derivedDataPath /Users/luchao/WorkSpace/MyAccountBook/.tmp-ios-build \
  CODE_SIGNING_ALLOWED=NO build
```

结果：**BUILD SUCCEEDED**。

⚠️ **必须传 `-derivedDataPath` 且指向项目内**。默认路径 `~/Library/Developer/Xcode/DerivedData/`
被沙箱拦截（`Unable to write to info file`），表现为 `BUILD FAILED`，**看着像代码编译不过，其实只是沙箱不给写**。
**判据是看日志末尾的 `** BUILD SUCCEEDED **`，不是看进程退出码** —— 收尾时沙箱还会拦一个无关的
`~/.swiftpm/security` 删除动作，让退出码非 0。

## 四、服务层：已定义但零引用（14 个）

判据：`grep -rn "<方法名>" --include="*.m" --include="*.h" .` 若只匹配到 `.h` 声明 + `.m` 定义两行，
即为零引用。

```
batchDeleteCategories   batchHideCategories   reorderCategories
deleteAccount           updateAccount         getDeletePreview
deleteCategory          getCategoryCandidates
getTransaction          importCategories
mergeAccounts           previewMerge          sharedCache   fromDictionary
```

其中影响功能完整性的：

- **`deleteCategory`** —— 分类**删除**接口就绪但 UI 未接（`grep -rn deleteCategory` 只有 2 行）。
- **`mergeAccounts` / `previewMerge` / `getCategoryCandidates` / `importCategories`** ——
  账本合并 + 从母本导入分类，正好对应上面缺的两个页面。
- `sharedCache` / `fromDictionary` —— 疑似设计冗余，可直接删。
