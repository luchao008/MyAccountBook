### 6. ⚠️ 三处 `size` 超限 —— **整页数据为空**（既有 bug，本轮修复）

列表接口的 `size` 上限是 **100**：

```bash
grep -n "size" src/transaction/dto/transaction.dto.ts
#   @Rule(RuleType.number().integer().min(1).max(100).default(20))
```

但 iOS 有三处传了超限值。**请求是被参数校验整条拒绝的，不是被截断的** ——
后端返回「输入有误，请检查后重试」，而调用方的 failure 分支只打一条 NSLog，
**界面上完全看不出来**：

| 位置 | 原值 | 症状 |
|---|---|---|
| `ABFlowViewController` 分组明细展开 | 500 | **点开分组永远空白**（流水页等于不可用） |
| `ABCalendarViewController` 月视图 | 500 | **日历上一个数字都没有** |
| `ABExportViewController` 导出 | 10000 | **导出功能一直是坏的** |

修法：服务层新增 `getAllTransactions:`，循环分页拉全量
（`PAGE_SIZE=100` / `MAX_PAGES=200`，退出条件与前端 `pages/export` 一致）。

**教训**：`编译通过` / `请求发出去了` / `接口返回 200` 都**不代表数据到了**。
`size` 这类**有上下限的数值参数**必须对着后端 DTO 核一遍，而不是"填个够大的数"。
发现路径也很说明问题：**是为了验证搜索才顺带看见明细是空的** ——
如果只验自己新写的那块，这个 bug 会一直躺在那儿。

### 8. ⚠️ ActionSheet 在 iPhone 上**没有「取消」按钮**（全局，既有 bug）

**根因**：所有调用处都设了 `popoverPresentationController`。在 iPhone 上这会让
iOS 26 **按 popover 呈现**，而 popover 模式会**自动省略 cancel** ——
`sheet.actions` 里明明有「取消」，界面上就是不画。

判据（一眼看穿的调试方法）：

```bash
lldb -b -p $PID -o 'po [(NSArray *)[[(id)$vc presentedViewController] valueForKey:@"actions"] valueForKey:@"title"]'
# 打印出「分类设置/改名/设为默认/合并到其他账本/删除/取消」—— 六个都在
# 但截图里只有五个
```

新增 `ABAlert.prepareSheet:anchor:in:` 统一处理：**只在 iPad 上配 popover**。
覆盖 8 处：流水筛选 / 排序 / 粒度 · 导出周期 / 分类 · 报表周期 · 记一笔日期 · 账本操作。

**说明**：iOS 26 上 iPhone 的 ActionSheet 渲染成**居中卡片**（不是底部抽屉）——
那是系统新样式、不是 bug；**修复点是让「取消」重新出现**。

### 9. 流水页**完整筛选面板** —— 已补（第四批，2026-09-25 晚）

**此前 iOS 的「筛选」只是个 6 项预设 ActionSheet**（全部时间 / 本月 / 本年 / 只看支出 /
只看收入 / 清除筛选）。前端 `FlowFilterPanel.vue` 是完整面板 —— 这是**上一轮浅查漏掉的一项**：
当时只看到 `filterKeyword` 属性就写了"iOS 筛选面板已支持 keyword"，实际连面板都没有。

新增 `ABFlowFilterViewController`（面板）+ `ABCategoryMultiSelectViewController`（分类多选）：

| 行 | 内容 | 对齐点 |
|---|---|---|
| 时间 | 6 预设（全部/本月/上月/本年/去年/自定义）+ 自定义起止 | 右侧**两行**：预设名 + 具体区间 |
| 分类 | 进分类多选页 | 空数组 = 全部；1 个 → `一级 / 二级`；N 个 → 「已选 N 项」（按**一级去重**计数） |
| 类型 | 全部 / 只看支出 / 只看收入 | 见下「三态等价」说明 |
| 金额 | 最低 - 最高 两个输入 | 输入层就拦非数字 / 多位小数；`0` 按未设处理 |
| 备注 | 关键词输入 | 与顶部搜索**共用 `keyword` 参数但是两个独立状态** |

外加：**已筛选提示条**（有任意条件即出现，「查看全部 ›」）+ **条件摘要弹层**
（逐条列出已生效条件，出口是「查看全部流水」/「修改筛选条件」）。

**「类型」为什么做成三选一而不是多选**：前端的 `types` 虽是数组，但
「全选（2 项）」与「全不选（0 项）」**都等于不过滤**，只有"恰好选中 1 种"才真的缩小结果集 ——
对外只有三种可观测状态。三选一的 ActionSheet 与多选弹层**语义等价**，也更符合 iOS 习惯。
（这不算"简化功能"，因为另外两种取值本来就产生相同的请求。）

**分类多选的三个不变量**（照搬前端）：
- 勾一级 = 连带其下全部二级；部分子被选中时一级显示**半选态**（金色横线圆）
- `root.id ∈ draft` ⟺ 该一级的全部二级也都在 draft 里 ——
  否则用户取消了一个二级、而 root.id 仍在，后端「传一级连带全部二级」会把那次取消**吃掉**
- 提交时**压缩**：一级已勾则只发一级；全选 / 全不选都发空数组（= 不过滤）

### 10. ⚠️「排序」菜单**点了毫无反应**（既有 bug，本轮修复）

`self.order` 属性存在、`onSort` 也给它赋了值 —— 但**它从没进过请求参数**。
菜单是真的、效果是假的，所以此前每次点排序都"通过"了（因为没有报错、也没有变化）。

前端把 `order` 传给的是**明细列表**（`/transactions`），而**分组汇总接口
（`/transactions/summary`）根本没有 `order` 参数** —— 所以排序只作用于展开后的明细。
补上后实测：同一天的明细按金额降序 88 → 9 → 8 → 6 → 5 → 5 → 2。

**教训**：控件不能只看"有没有"。要看**输入最终有没有到达后端** —— 见
`docs/工程约定与踩坑.md` §五 第 14 条。

### 11. 流水页「按分类分组」—— 已补（第五批，2026-09-26）

前端的底栏是**两个互斥的分组维度**：`时间(粒度)` 与 `分类(一级|二级)`。
iOS 只有粒度 —— **「按分类分组」这个视图模式整个没有**（更微妙的是，
`ABFlowGroupCell` 里**早就有** `isCategoryGroup` 分支，但入口从没接上，是段死代码）。

补上的东西：

| 项 | 实现 |
|---|---|
| 底栏 | 「月（粒度）」「分类（层级）」两个维度按钮 + 筛选 / 排序；**在用的那个显示当前取值并高亮**（对齐前端 `.active`） |
| 互斥 | 点粒度 → 同时把 `groupBy` 切回 `time`；点分类 → 切到 `category`。⚠️ 只改其一的话，从「二级分类」点「月」会**仍按分类分组** |
| 参数 | `time` → `groupBy=time&unit=…`（**不带 level**）；`category` → `groupBy=category&level=N`（**不带 unit**）。混传不报错，只是那个字段被忽略 |
| 组头 | 分类维度标题是**分类名**、副标题是**所属一级**（二级口径）；时间维度仍是「9月 / 2026」 |
| 组头金额 | 补上**结余**（原来只有 收入\|支出），并对齐前端：结余按正负着色、收入红、支出青绿 |
| 展开明细 | 分类组用**全局筛选的 start/end** + `categoryIds=本组分类`。少了时间会"筛本月却冒出别的月"，少了分类会"展开出来是全部流水" |

**顺带修**：组头箭头原来用 `chevron.right` 旋转 90° 表示展开，现在是 `chevron.down/up`。

#### ⚠️ 「未分类」组有意做成**不可展开**（与前端不同）

后端 `categoryIds` 只能传**真实分类 id**（外加"一级连带其下二级"的展开），
**没有任何方式筛出 `category_id IS NULL` 的流水**。

前端在这一点上是不传 `categoryIds` 直接查 —— 于是**展开「未分类」看到的是该时段全部流水**
（汇总金额是那一笔，明细却是全部）。**这是前端自己的 bug，没有照搬**：
iOS 侧「未分类」组**不画箭头、也不可选中**，宁可不展开也不给一个"点得动、结果不对"的列表。

（本地过滤是另一条路，但"全部时间"下等于拉全量，代价太大，不做。）

### 12. 两个顺带修掉的问题（第三批）

- **账本 cell 把内部 key 当图标显示**：`acc.icon` 的值是 `"wallet"` 这种 key，
  拼进 `textLabel` 就显示成字面量。**前端账本列表本来就不显示图标**，跟着对齐即可。
- **`refreshWithCompletion:` 不回退 currentId**：它只更新 `list`。
  `loadWithCompletion:` 才有「当前账本不存在 → 回退到默认账本」的逻辑。

  **之后所有按账本取数的请求全部失败**，症状是「页面一片空白」。

## 三、四条 UI 层面的通用教训（实测踩到，都会静默出错）

### 0. 两个视图的约束**重叠 = 一个被另一个盖住**，而且完全不报错

分类多选页的一级行左侧同时有「折叠箭头」和「分类图标」。第一版把图标放在
`left: 16`、箭头放在 `left: 8`，箭头宽 20 —— 两者区间重叠，而**图标是后加的**，
于是箭头被完全盖住：**渲染无异常、约束诊断全绿、点击也正常，就是"箭头根本看不见"**。

判据：**只能看图**。改法是给前一个元素**让位**（图标右移到 30）。
（同类：`pointer-events` 那一条 —— 也是"几何探针永远查不出"的一层。）

### 1. 高度归零的容器**必须 `clipsToBounds`**，否则子视图按 centerY 溢出

`searchBar` / `sortHint` 靠"高度约束设 0"来隐藏。但里面的 label / 输入框按 `centerY` 居中，
高度为 0 时它们会**溢出到容器上下两侧**，在顶栏下面露出一条被裁掉一半的残影。
三个模式都会露。修法：容器 `clipsToBounds = YES`。

### 2. 内容撑开的容器：label 的**垂直 hugging 必须是 required**

`headerCard` 高度靠内部 label 撑开。第一版实测被拉成 **582pt**（应为 ~66），
把下面的 tableView 挤到只剩 **79pt**。

根因不是约束冲突，是**约束不足**：约束链只给出上下界，UILabel 的 intrinsic 高度只是
**251 优先级的软约束**，求解器仍有自由度去吸收剩余空间。

判据：`_autolayoutTrace` 报 `AMBIGUOUS LAYOUT for UIView.Height`。修法：

```objc
[label setContentHuggingPriority:UILayoutPriorityRequired forAxis:UILayoutConstraintAxisVertical];
```

### 3. 表格页别用 `registerClass:` + `dequeueForIndexPath:` 却指望 `detailTextLabel`

那样拿到的是 `UITableViewCellStyleDefault`，`detailTextLabel` **恒为 nil**，副标题永远不显示，
**不报错、不崩溃**。要么去掉 `registerClass:` 手动 `initWithStyle:UITableViewCellStyleSubtitle`，
要么别用副标题。

| `/statistics/monthly` | **前端零调用** —— `getMonthlyStat` 只在 `api/statistics.ts` 里定义，没有任何页面用它。**是死接口**，iOS 不实现是正确的。 |
| `/statistics/category` | 前端首页用它出「本月各分类支出排行」。iOS 首页走 `getReport` 取 `expenseCategories` —— 与它**口径完全相同**：后端 `categoryInRange` 的一级归并与 `categoryBreakdown` 都是「按一级聚合 + 同款 ratio」，唯一差别是 `/category` 多带一个 `count`（前端首页也没展示它）。 |

**结论：确实不缺，不需要补。** 这条是"实测确认"而不是"看文档抄的"。

**筛选「真的到了后端」也验过**：设 `type=expense` 后头部「收入」变 **0.00**（原 16,000.00）——
这不只是"界面看起来变了"，是请求参数确实改变了服务端结果。

**分组维度切换也验过**：底栏「月 / 分类」两格 + `level` 1/2，四个组合各自截图（23–26）。
结果符合预期，其中 `unit` 与 `level` **互斥地进参数**（时间维度带 `unit` 不带 `level`，

**错误路径也验过**：给一个不存在的 accountId，页面提示「候选分类加载失败：账本不存在」——
说明加载失败会报出后端真实原因，不会伪装成"没有可导入的分类"。

### 一处有意偏离前端

「未分类」组（`__none__`）**不给展开箭头**，其余组都有。前端在这里是可展开的，但展开后
会走「按未分类过滤」—— 而后端**不支持**这个过滤，点了只会拿到空列表。所以 iOS 侧直接
去掉箭头（同时 `willSelectRowAtIndexPath` 返回 nil），让这个无效路径根本不可达。

### 没跑过的（只保证编译通过）

- 导入页**有候选时**的勾选树渲染 —— 所有现成测试账本都已含全部分类，候选被过滤为空
- 拖动排序的**实际拖拽手势**（`moveRow` 回调里的一级 / 二级搬移算法）
- 批量删除 / 隐藏的**实际提交**
- 分类页的**滚动**表现
- **筛选面板里的手势路径**：日期选择器（`UIDatePicker` 滚动与确认）、金额框的**真实键盘输入**
  （只验了 `shouldChangeCharactersInRange:` 的逻辑，没敲过键盘）
- **金额区间 / 备注 / 时间区间三个条件**只验了「类型」一个 —— 它们走同一段 `applyFilterTo:`，
  但参数拼装的具体分支没逐个跑

### 靠"绕过"验的（验的是同一段逻辑，但没走真实交互路径）

- **搜索的输入**：`simctl` 敲不了键盘，改成 `setText:` + 直接调 `doSearch`。
  测的是同一段处理代码，但**没覆盖** `UIControlEventEditingChanged` 那条路径
  （即「边打字边清空结果」）。
- **导出**：直接调 `onExport`，不是真的点按钮；分享面板之后的动作（保存到文件等）没验。
- **筛选面板的「确定」**：直接调 `onConfirm`，没走真实的按钮点击 → 但按钮与它的 target/action
  关系是编译期可查的，风险低。
- **分类多选的勾选**：直接调 `tableView:didSelectRowAtIndexPath:`，**没测折叠箭头那条分支**
  （箭头走的是 `onCaretTap:`，与行选中是两条独立路径 —— 箭头是 UIControl，会吃掉触摸）。
